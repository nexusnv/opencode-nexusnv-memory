# Changelog

## Unreleased

- Docs split: the README is rewritten for users (install, workflow, lifecycle, options, privacy, troubleshooting, uninstall), while contributor material (local/drop-in setup, architecture and invariants, manual mode, eval/deploy gates, compatibility, PR checklist, release process) moves to `CONTRIBUTING.md`. The `/memory-status` capture-activity guidance now says to use the session normally and re-check instead of pointing at a README deploy check that moved.
- Tier-3 context/lifecycle/concurrency (E8/E13/E14): the stable active-context brief stays in the per-model-call system prefix, while the newest-handoff pointer, status line, and hint are appended once per prompt as ≤3 marker-guarded data lines (INDEX ≤30 + brief ≤47 + notices ≤3 = ≤80; session-total 237 at 4 steps, an uncached line guardrail, not a billed-token claim). `/memory-forget` is dry-run by default and archives redacted lines under `handoffs/archive/` before a per-unit-approved rewrite; `decisions.md` and handoffs are rejected, and the command states that git history/backups may retain content. `/memory-gc` is opt-in, dry-run by default, root-handoffs-only, and never touches archive. All memory-file writes now use a same-host PID/claim lock (`.write.lock`) plus temp+rename/link publish; two host processes either serialize or fail with a clear 5 s timeout. The compaction priors now carry Known-Errors **summary lines only** — raw captured detail stays `memory_recall`-only in every auto-injected path. No model-facing delete tool, no sixth option, no new metric name; FTS/TTL/decay/TUI remain out of scope.
- Tier-2 ledger hygiene (E9): snapshot values are `{ hash, at }` (legacy bare-hash strings are normalized out on the first prune); a new `pruneLedgerState` removes aged attempts (30s retry window), hint throttles (7 UTC days), and snapshot/throttle stamps (30 UTC days) using paginated scans outside the write lock and one lock per victim for the re-read + remove pair, piggybacked on the existing once-per-UTC-day metrics pass. `seen` stays capped at 500; malformed values are left alone; idempotency guarantees are unchanged.
- Tier-2 metrics dashboard (E10): counter rows gain a fixed human-readable `meaning` column (`counter | meaning | count`; bucket view `day | counter | meaning | count`) from the exhaustive `METRIC_LABELS` map — display furniture only, never input-derived. Reset is now two-step: bare `/memory-metrics reset` renders the dashboard plus a confirmation notice without wiping (and carries the notice on the fallback prompt), while `/memory-metrics reset confirm` wipes the namespace and bumps `dashboard.reset`. No new counter name; the vocabulary stays the frozen 45 names and ADR-0006's five options are untouched.
- Tier-2 hint nudge (E11): when the latest user text looks like a `remember:` attempt but is not the documented line-start form (`Please remember: X`, bare `remember:`, …), the prompt hook fills its one hint slot with a fixed one-line nudge explaining the exact form. It shares the existing prompt-hash throttle with `matchIndex`, never writes memory, and never arms hint→recall (only a real INDEX tell-tale does). Valid directives, narrative uses (`remember when/how…`), and fenced/quoted text stay silent.
- Tier-2 onboarding (E12): first run now emits one consolidated install checklist (required `memory_write → ask` rule, `AGENTS.md` protocol block, commented options snippet, `/memory-status` pointer) instead of a separate warning + dump; later setups keep the unconditional permission warning. README gains a five-step Quickstart and the setup/metrics/uninstall docs reflect two-step reset and ledger retention.
- Tier-0 UX hardening (E1, E3–E6): a fresh scaffold no longer injects placeholder text into the brief or priors (placeholders are HTML comments; legacy `- (…)` placeholders, comment-only lines, and empty sections are filtered from auto-injection). Silent degradations now surface on the `[memory]` status line: an over-cap `INDEX.md` (line count vs cap, cleared after reporting) and failure captures whose append the write guard rejects (`failureKind: "write-rejected"`, count-only). A non-first-run project whose root `AGENTS.md` exists without the memory protocol block gets a once-per-process install nudge. `memory_recall` lists handoffs names-only (`file: "handoffs"` / `"handoffs/archive"`), missing files report `memory file not found: <name>` with a listing hint, and non-allowlisted paths enumerate the valid names. The `[memory-hint]` line calls the structural file its matched INDEX line maps to (default `decisions.md`). `parseMemoryOptions` warns once on `injectBudgetLines <= indexLines` and `fileLines < 10`. No new option, no new metric name, no memory-file write behavior change.
- Tier-1 status (E2): `/memory-status` + the read-only `memory_status` tool render a deterministic install/health report (scaffold, INDEX attachability, AGENTS.md protocol block, advisory `memory_write → ask` scan, optional `memory-manager`, capture activity, budgets/version/since/latest handoff, next actions). A missing `INDEX.md` reports `missing — not attached` with a restore action instead of a 0-line "ok", and the advisory JSONC scan requires `action: "memory_write"` + `effect: "ask"` on the same object (sibling rules do not combine). The command posts via `ctx.session.synthetic` (no model turn) and falls back to the §5.5 `memory_status` echo prompt; it never throws, writes nothing, and bumps no counter. Optional `commands/memory-status.md` stub ships alongside (plugin command is normative).
- Tier-1 search (E7): `memory_search` greps the full allowlist — including the `decisions.md` tail that capped recall drops and archived handoffs — for an exact literal string, case-insensitively by default. Same traversal/allowlist choke point and redaction as recall via `readFullRedacted`; 1 MB per-file guard, 200-candidate cap, 20 default / 50 max results, deterministic structural → root handoffs → archive order. A truncated read stops at the last complete line so a credential split at the byte guard cannot surface; overlong URL credentials also redact (the scheme stays bounded; userinfo/password match to the `@`). The read boundary opens first and validates the opened inode (realpath containment plus `dev`/`ino` identity), closing a check-then-open race; non-regular files reject. No counters, no writes, no new storage keys; results are untrusted data and are never auto-injected. The URL-credential, generic-key, private-key, and `<private>` tag patterns are bounded/fail-closed for linear-time full-file reads.
- Security hardening for Tier 1: recall and search resolve real paths and reject symlinks that escape `.opencode/memory` (a symlink inside the root is allowed); search redaction preserves line counts so reported hits match the on-disk line; a single unreadable/mislinked candidate is skipped in the default search scope, while an explicit `file` scope still rejects.
- Docs/protocol/tests for Tier 1: the AGENTS.md Read bullet mentions `memory_search`; spec §§5.13/5.14, US-30/31, HS-13, C4 interfaces/data/code, README tools/commands/deploy/evals (static 16, per-prompt 96, session 237, an uncached line guardrail), and exact setup-surface assertions are updated.

## 0.2.0 (2026-10-18)

- Local usage metrics (spec §5.12, ADR-0008, M-T1–M-T6): count-only, on-machine, never-throw `bump` taps over the plugin-scoped `ctx.storage` (`<projectID>/metrics/…` — monotonic totals + ≤90-day UTC buckets + lazy `since`, enumerated fail-closed names, numbers only, 1,000-bump flood containment); metrics health (six structural file line counts, handoffs/archive/pending/seen counts via the shared scan walker); the read-only `memory_metrics` tool; and the `memory-metrics` command registered at setup (`/memory-metrics [reset]`): synthetic-post dashboard → once-per-process G-M1 deploy line → §5.5 `memory_metrics`-echo fallback on a rejected post. Optional file-based `commands/memory-metrics.md` affordance ships alongside (plugin command is normative, later source wins). No memory file, budget, injection, or hook-outcome behavior changes.
- Five-option config contract unchanged (ADR-0006: metrics always on, no sixth option; `/memory-metrics reset` is the control; uninstall orphans the keys like the ledger).
- Review hardening (M-T1–T7 follow-up): the §5.12 hint→recall arm consumption is atomic (`consumeArm`: read + clear in one locked body, so concurrent recalls convert an armed session at most once), and `/memory-metrics reset` wipes under one lock (scan + removes + fresh `since` serialize against in-process bumps); no counter definitions, key shapes, or hook outcomes change.
- Arm lifetime (PR #13 review): arm entries store a positive-int arming timestamp and arm for at most one UTC day — `readArmed`/`consumeArm` age the value out live (a stale hint can no longer inflate `hint.recall`), and the daily piggyback prune also clears aged `metrics/arm/…` entries, so hinted-but-never-recalled sessions stop accumulating keys. Still numbers only (the number-only invariant gate holds).

Supported OpenCode range: `2.0.x` (built and type-checked against `@opencode/plugin 2.0.29`).
