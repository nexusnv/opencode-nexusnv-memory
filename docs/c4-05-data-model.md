# Supplementary Spec B — Data Model (file schemas are the model; no database)

**Status:** proposed. **Sources:** Synthesized Report §§4.1–4.5, 4.8. **Normative on V2 contracts:** `design-spec-v2-production.md` §6. (Numbered `c4-05` for sequence; not a C4 core level — C4 has four levels; see `c4-06-code.md` note.)

## Files

| File | Fields | Cap |
|---|---|---|
| `INDEX.md` | `topic → file:section` lines, ≤30 | 30 lines |
| `activeContext.md` | goal / pending / next / known-errors (scratchpad: append-until-60, then rotate oldest Known-Errors block to `handoffs/archive/`; the rotation is announced once via the `[memory]` status line). Known Errors are message-derived `summary line (source:<origin>)` + indented **recall-only** detail block (≤20 raw lines); only summary lines are injectable (max 5 per brief; `<cmd>:` prefix only when `event.input` yields it) | 60 lines |

| `handoffs/archive/<name>.md` | retired durable lines + rotated scratchpad blocks; recallable on demand via `memory_recall`, never auto-injected | per file 60 lines |
| Ledger (`ctx.storage`) | `<projectID>/seen/<contentID>` + `<projectID>/attempt/<contentID>`, plus `<projectID>/curation.pending` (scratchpad-only count) and `<projectID>/curation.rotated`, plus `<projectID>/snapshot/<sessionID>` (`{hash, at}`; legacy bare-hash strings normalize out on the first prune), `<projectID>/snapshotThrottle/<sessionID>`, `<projectID>/hint/<sessionID>/<promptHash>`, plus `<projectID>/notice.indexOverCap` / `<projectID>/notice.captureFailed` (transient positive-int status notices, cleared after reporting); 30s retry window; persisted, never in-memory alone (`ctx.storage` is plugin-scoped); single-flight per content ID (the API has no CAS); `seen` pruned via `scan({prefix:"<projectID>/seen/"})` with `after`/`next` pagination to ≤500 entries; aged attempts (30s), hints (7 UTC days), and snapshot/throttle stamps (30 UTC days) removed by `pruneLedgerState` on the daily metrics piggyback (scan outside the lock, re-read under `withWriteLock`) | bounded |
| Metrics (`ctx.storage`, ADR-0008 / spec §5.12) | `<projectID>/metrics/total/<name>` (int, monotonic until reset) + `<projectID>/metrics/day/<YYYYMMDD>/<name>` (int, pruned after 90 UTC days via paginated scan+remove) + `<projectID>/metrics/since` (first-write timestamp) + `<projectID>/metrics/arm/hint/<sessionID>` (transient arm entry: a positive-int arming timestamp when armed, armed ≤ one UTC day, consumed on first use or cleared by the daily prune); values are **JSON numbers only** — no content ever; names come from the enumerated fail-closed vocabulary; counter tables render the fixed `METRIC_LABELS` meaning column (display prose only); writes serialize through the same per-process mutex; `reset confirm` removes the entire `<projectID>/metrics/` namespace and re-stamps `since` (bare `reset` only renders the confirmation notice) | ≤ enumerated totals + ≤90 day buckets × actually-bumped names + ≤ hinted sessions in the last UTC day |

**Tier-1 status/search (E2/E7) add no storage keys.** `memory_search` reads the existing allowlist in full through `readFullRedacted` under a 1 MB per-file guard; it writes nothing and bumps no counter. `/memory-status`/`memory_status` read existing counters (`snapshot.*`, `compactionCapture.*`), on-disk line/entry counts, and install markers (AGENTS.md, readable configs, agent registry) only; they write no storage and emit no memory body. The command's synthetic post is a session message, not durable plugin state; uninstall leaves no new namespace to purge.

**Tier-2 retention (E9/E10) adds no new ledger or metric keys.** The only ledger changes are the `{hash, at}` value shape for the existing `<projectID>/snapshot/<sessionID>` key and age-based pruning of existing keys (`attempt/`, `hint/`, `snapshot/`, `snapshotThrottle/`) on the existing daily metrics piggyback; idempotency semantics are unchanged. The only metrics changes are fixed display labels and the two-step `reset confirm` control; the frozen 45-name vocabulary gains no name.

## States and retention matrix

States: scratchpad → durable → archived (git). Retention = reachability: active (retain + injectable suffix) / causal (retain, follow-on-demand) / conditional (INDEX one-liner) / archived (`handoffs/archive/` for retired lines, recallable on demand via `memory_recall`, never auto-injected; session snapshots stay at `handoffs/` root). Reachable decisions are decay-exempt; age-based forgetting touches only unreachable episodic notes.

## Budgets

Auto-inject payload (prompt `INDEX.md` attach + context brief + status line + hint): `INDEX ≤30 + brief ≤48 (incl. max 5 error lines) + status ≤1 + hint ≤1` (~1.5k tokens per model call, excludes static root `AGENTS.md` directive + retrieval-policy descriptions: 16 lines total, measured — 6 non-empty protocol lines + 5 wrapped `memory_recall` + 5 wrapped `memory_search`). `INDEX` attaches once per prompt; the brief/hint/status are re-emitted per model call, so session-total = per-prompt × model steps (the hint is throttled via `<projectID>/hint/<sessionID>/<promptHash>`; when it is the fixed `remember:` near-miss nudge it is still exactly one line — no count changes). The decisions tail travels via `loadPriors` (compaction) + recall only, never the per-call brief. Content overflow → `handoffs/archive/`; session snapshots → `handoffs/` root; never the prompt. The status line carries the rotation notice and the review-due nudge (≥5 uncurated scratchpad captures), plus the over-cap `INDEX.md` notice and the skipped-capture notice (Tier 0 — numbers only) so uncurated memory is surfaced — but it is **model-facing** (`event.system`), so the agent relays it rather than the user seeing it directly. **Captured command output never enters the payload as a body** — only the message-derived summary line (P16). Enforcement: write caps (`INDEX/activeContext/architecture/style/issues` on plugin writes; hand-edits validated by review) + read caps (`decisions` tail, handoffs via `readCapped`) + injection caps (hook payloads via loaders).

## Trust model

Every entry carries a provenance tag (`source:user | tool | model | snapshot`). Content from `tool`/`model`/`snapshot` is untrusted: it may be auto-injected (summary line only) but never promoted to a durable file without explicit per-line human approval, and untrusted candidates are excluded from bulk approval. The review's read+propose phase writes no memory and only produces a proposal table (its only side effect is the §5.12 `review.invoked` counter — count diagnostics, no content); every write is per-line approved through `memory_apply`. It is not sandboxed (a session permission lock is time-scoped and would deny the user's own tools — retired G5); the optional read-only `memory-manager` subagent confines poisoned text to a child session when used. Memory files are data, never instructions (ADR-0007).
