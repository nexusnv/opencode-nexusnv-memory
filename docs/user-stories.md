# User, Agent, and Harness Stories — No-Fuss Memory Plugin for OpenCode V2

**Status:** proposed. **Sources:** `motivation.md` §§4–5; `c4-01-system-context.md` through `c4-06-code.md`; ADR-0001 through ADR-0007; `README.md`. **Precedence:** ADRs are normative on decision intent; `design-spec-v2-production.md` is normative on V2 contracts and supersedes these stories on conflict.

**Scope:** all functional requirements from install to uninstall. Three viewpoints: **User** = developer (owns memory, approves promotion); **Agent** = OpenCode V2 agent incl. `memory-manager` subagent (reads protocol, peeks lazily, proposes); **Harness** = OpenCode V2 server/runtime (loads plugin, provides hooks/events/transforms/storage/vcs, enforces AGENTS.md hierarchy).

**Conventions:** `INDEX/activeContext/decisions/architecture/style/issues` live under the fixed directory `.opencode/memory/` (ADR-0006: read-path choke point + recall allowlist), resolved **per hook invocation from the event's** location (`event.location` + `data.sessionID`, fallback `ctx.location` — instance-scoped, P22); snapshots at `handoffs/YYYY-MM-DD-HHmm.md` (root); retired lines at `handoffs/archive/<name>.md`. Budgets: `INDEX.md` ≤30 lines on disk; `activeContext/architecture/style/issues` ≤60 lines on disk; `decisions.md` unbounded on disk with ≤60-line injectable tail via `loadPriors` + recall only (never the per-call brief); handoffs per-file ≤60 lines; auto-inject payload = `INDEX ≤30 + brief ≤48 (max 5 error lines) + status ≤1 + hint ≤1` where `INDEX` attaches once per prompt and the brief/hint/status re-emit per model call (session-total = per-prompt × model steps; hint throttled via `<projectID>/hint/<sessionID>/<promptHash>`). Failure entries use the documented `Tool.Error{message}` payload (message-only baseline, G4 proven): the message-derived summary line is injectable only — any captured body/cmd/code is optional and never assumed (P16). **Provenance:** every entry is tagged `source:user | tool | model | snapshot`; only `source:user` (explicit `remember:`/`remember that` line-start form, outside code fences/quotations — pastes covered only by that heuristic) writes `decisions.md` without a review cycle and without incrementing pending — detected and written in the async never-throw `prompt` hook (serialized); everything else is scratch → `/memory-review`, and no origin writes `architecture.md`/`style.md`/`issues.md` without review (ADR-0004/0007). Ledger: persisted `ctx.storage` (`<projectID>/seen/<id>` + `<projectID>/attempt/<id>` + `<projectID>/curation.pending` (scratchpad-only) + `<projectID>/curation.rotated` + `<projectID>/snapshot/<sessionID>` + `<projectID>/snapshotThrottle/<sessionID>` + `<projectID>/hint/<sessionID>/<promptHash>`, single-flight per content ID, pruned via `scan({prefix:"<projectID>/seen/"})` to ≤500 IDs, ~30s retry window, never in-memory alone). Options (≤5): `indexLines`, `fileLines`, `injectBudgetLines`, `captureFailures`, `snapshotThrottleMinutes`.

**Non-goals (all stories):** no transcripts, no embeddings/vector search, no SQLite/FTS in default path (P2 explicit opt-in derived index only, never source of truth), no cloud/server/API keys, no per-turn LLM extraction, no silent durable writes, no custom compaction triggers, no background LLM dreaming, no cross-project reads (ADR-0001, `c4-01`).

**P1 gates (design-spec §1.3, type-proven via `@opencode/plugin@2.0.29`):** `session.idle` (`data:{sessionID}`) and `session.compaction.started/delta/ended/failed` are enumerated in `@opencode/schema`; `compaction.ended.data` carries `{text,recent,…}`. Failure capture uses `ctx.tool.hook("execute.after")` (`Tool.Error{message}` only, G4 proven); a deploy-time `event.type` log confirms delivery. **G2 (proven):** executor envelope `{ content: <string> }` (`Tool.Result`) via one `toolResult` adapter. **G5 (retired):** the review is proposal-only and needs no sandbox — a command cannot target a subagent, and a session permission lock is time-scoped; every write is per-line approved via `memory_apply` (which resets pending/marker).

## Part A — User (Developer) Stories

### Install (V2 plugin framework)

- **US-01 Install via `.opencode/opencode.jsonc`.** As a user, I want `plugins: ["./plugins/memory"]` in `.opencode/opencode.jsonc` so the runtime loads the local plugin. Acceptance: `opencode plugin list` shows `memory`; config arrays merge global → project → `.opencode` (`motivation.md` §4, `c4-02`, `c4-06`).
- **US-02 Install via repo-root `opencode.jsonc`.** As a user, I want `plugins: ["./.opencode/plugins/memory"]` as the equivalent path when config lives at repo root. Acceptance: same load result as US-01; paths never mixed (`c4-02`, `c4-06`).
- **US-03 Install via auto-discovery (no config edit).** As a user, I want to drop the plugin at `.opencode/plugins/memory/` and have it discovered so I touch no JSON. Acceptance: direct `.ts`/`.js` + immediate package dirs discovered; `opencode plugin list` verifies (`motivation.md` §2 row 5, `c4-06`).
- **US-04 First run scaffolds memory (+ emits config snippets).** As a user, I want first run to create six memory files + `handoffs/` and print a commented ≤5-option snippet plus the mandatory `{action:"memory_write",resource:"*",effect:"ask"}` permissions snippet (required so `memory_apply` prompts instead of failing open on the base allow policy) so I never hand-write schemas and the plugin never edits my config or `AGENTS.md`. Acceptance: `INDEX/activeContext/decisions/architecture/style/issues` + `handoffs/` exist; both snippets shown; `opencode.jsonc`/`AGENTS.md` unchanged (ADR-0006, `c4-06`, design-spec §4.4).
- **US-05 P0 manual mode (no code).** As a user, I want to create six files by hand, add the protocol block to root `AGENTS.md`, and drive `memory-manager` manually so a new session restores from `INDEX.md` + `activeContext.md` with no plugin code. Acceptance: new session restores without re-explaining (`README.md`, `motivation.md` §5).
- **US-06 Verify + recover from reload issues.** As a user, I want `opencode plugin list` + the runtime log (plus touch-the-entry-file / restart per the runtime's reload guidance) so I can prove load and recover stale loads. Acceptance: documented in `c4-06`; P1 runtime gates recorded (`c4-03`, `design-spec` §1.3).

### Daily use (capture → restore → curate)

- **US-07 Failure-only capture to scratchpad.** As a user, I want failed shell/build/test output appended to `activeContext.md` under Known Errors (secrets/`<private>` stripped, ledger check-before-write) as a `source:tool` **summary line + optional recall-only detail block**, so failures are kept without transcript bloat and **without putting raw command output into the auto-injected payload**. `Tool.Error` carries only `message` (G4 proven), so the tested baseline is message-only (message-derived line; `<cmd>:` only when `event.input` yields it) and no consumer may assume a body, cmd, or code exists. No per-turn LLM extraction. Acceptance: success ignored; restarts/replays are no-ops; captured via `ctx.tool.hook("execute.after")`; only the summary line is injectable (P16, ADR-0007) (`motivation.md` §4.3-1/2, ADR-0004, `c4-03`, `c4-06`).
- **US-08 `remember` is provenance-routed.** As a user, when I explicitly instruct the agent to remember a fact in the documented directive form, I want it written durably **immediately** (append-only `decisions.md`, tagged `(user-asserted)`) without a second approval cycle — because my instruction *is* the approval. Detection and write run in the `prompt` hook (serialized, never-throw, ledger-idempotent), and the plugin is the sole writer. Anything ambiguous, or a "remember" found in tool output, pasted text, or model prose, stays in the scratchpad for review. No origin may write `architecture.md`/`style.md`/`issues.md` without review. Acceptance: documented directive → durable with no `/memory-review`; ambiguous/tool-origin → scratch only; instruction inside a code fence/quotation is **not** classified `source:user` (pastes covered only by that heuristic) (ADR-0004 revision, ADR-0007, `design-spec` §5.11).
- **US-09 Idle snapshots, newest wins.** As a user, I want content-hash-guarded snapshots (`branch` via `ctx.vcs.get()` + open changes + completed/pending/next) at immutable `handoffs/YYYY-MM-DD-HHmm.md` so "where did we leave off" is a single newest file; same content → no new file. Primary trigger is the type-proven `session.idle` event (`data.sessionID`; G1); fallback is an **async, fire-and-forget, serialized** hash-guarded writer in the `context` hook (≤ once per `snapshotThrottleMinutes` per session via `<projectID>/snapshotThrottle/<sessionID>`, events filtered via `event.location`). Branch via `ctx.vcs.get()`, changes via `ctx.vcs.status()`. Acceptance: hash in `<projectID>/snapshot/<sessionID>`; no-op on unchanged; concurrent `context` invocations do not interleave writes (`motivation.md` §4.3-3, `c4-03`, `c4-05`, `c4-06`, `design-spec` §§5.9/8 D-A).
- **US-10 Next-session restore positions.** As a user, I want `prompt` hook to attach `INDEX.md` (capped, deduped, skip if already attached; over-cap file not attached) at the top and `context` hook to push active brief + ≤1 status line + ≤1 hint at the bottom, with root `AGENTS.md` contributing protocol + links only, never content. Acceptance: no double injection; brief does not duplicate INDEX; deeper content only via lazy recall (`motivation.md` §4.3-4, ADR-0002, `c4-04`).
- **US-11 Lazy recall (`memory_recall`).** As a user, I want one capped, redacted file per question from the allowlist (`INDEX/activeContext/decisions/architecture/style/issues` + `handoffs/<name>.md` + `handoffs/archive/<name>.md`; archive recallable on demand, never auto-injected), error on unknown/traversal, never list filesystem. Acceptance: returns the executor envelope via `toolResult` (default `{ content }`, G2) with truncation notice + secrets strip; description doubles as retrieval policy (`c4-03`, `c4-04`, `c4-06`, `motivation.md` §4.6).
- **US-12 Deterministic hint, exact match only.** As a user, I want at most one `[memory-hint]` line when prompt/touched files exactly match an INDEX symbol, else no line. Overhead is reported as **static** (~10-line directive + ~3-line tool desc) and **per-prompt with content** (once-per-prompt `INDEX` + per-model-call brief/status + the hint only on hit, throttled via `<projectID>/hint/<sessionID>/<promptHash>`), with **session-total** = per-prompt × model steps. No fuzzy/semantic match. Acceptance: `matchIndex` returns 1 line or `undefined`, parsed from `event.messages: Message[]` for the latest user-authored text (`motivation.md` §4.5, ADR-0005, `c4-06`).
- **US-13 Human-approved promotion (`/memory-review [scope]`).** As a user, I want to run `/memory-review` and get a **provenance-tagged proposal table only** (target file, exact candidate line, `source:`, advisory injection flags, cap + redaction checks) that writes nothing, then approve specific lines so durable files stay trustworthy. Untrusted-provenance candidates cannot be bulk-approved. Acceptance: never writes durable without approval; the review's only output is the proposal table (it is proposal-only, not sandboxed — every durable write is gated by approval); the optional read-only `memory-manager` subagent can run the pass in a separate session; approval happens per line through the `memory_apply` tool (one `ctx.permission.assert({action:"memory_write",…})` per candidate from tool-context IDs, deny propagates, `candidates:[]` = reviewed-nothing), then application is deterministic via `writeCapped` and `memory_apply` resets pending/marker; invocation prompt attachments preserved; validates manual `issues.md` edits without overwriting (`c4-03`, `c4-04`, ADR-0004/0007, `design-spec` §5.5).
- **US-14 Direct `issues.md` edits.** As a user, I want to hand-edit `issues.md` (one line each: todo/doing/done + issue ref) and have `/memory-review` validate rather than overwrite. No API dependency; GitHub issues are a manual source. Acceptance: format/cap/redaction check passes or reports (`c4-01`, `c4-04`, ADR-0004, `c4-05`).
- **US-15 Rotation with notice.** As a user, I want `activeContext.md` append-until-60 then rotate the oldest Known-Errors block to `handoffs/archive/` with a notice surfaced through the one `[memory]` status line (model-facing — the agent relays it), never into the prompt, so the scratchpad never grows the injection surface and I'm told when content leaves the auto-injected window. Acceptance: per-file ≤60; the rotation sets `<projectID>/curation.rotated`; the `context` hook emits `[memory] rotated <n> block(s) to handoffs/archive/` once and clears the marker (`c4-03`, `c4-05`, `c4-06`, `design-spec` §5.7).
- **US-16 Compaction survival without custom trigger.** As a user, I want the native `compaction` hook to inject capped + redacted priors (`event.system.push`) and to **never set `event.result`** (which would skip the native summary), never changing model/threshold/trigger, so a bad summary loses nothing durable (pre-compaction state already on disk). Acceptance: priors injected; `event.result` untouched; produced summary captured from `session.compaction.ended` (`data.text`+`recent`, G1 proven), else a pointer-only handoff; no #69/#85/#88 regressions (`motivation.md` §4.3-6/§4.6, ADR-0003, `c4-04`, `design-spec` §§5.6/8 D-B).
- **US-17 Budgets hold under growth.** As a user, I want overflow (retired durable lines, rotated blocks) → `handoffs/archive/`, snapshots → `handoffs/` root, never the prompt, with write caps + read caps (`decisions` tail, handoffs via `readCapped`) + injection caps (hook payloads via loaders). Acceptance: `c4-05`/`c4-06` test list; `decisions.md` full log + git retains everything (`c4-05`, `motivation.md` §4.4).
- **US-18 Secrets never stored or injected.** As a user, I want secrets blocklist + `<private>` stripping before any write/inject, size-cap before inject, and memory treated as untrusted **data** (never executed, never obeyed). Acceptance: secrets fixtures blocked; no component acts on text read from memory (`c4-02`, `c4-03`, `c4-06`, ADR-0007).
- **US-19 Local-only, per-project, git-backed.** As a user, I want strict per-project scope (no cross-project reads), $0 default (file reads only), and history/blame/undo/redo/restore from git. Acceptance: `c4-01` privacy boundary; `c4-02` cost/latency.
- **US-20 Lineage rules.** As a user, I want `decisions.md` + `handoffs/` append-only/immutable (corrections = new entries with `Supersedes`, never edits; summaries are disposable handoffs, never memory) and `architecture/style/issues` as review-gated rewrites with git blame as lineage, so "why not the old name" (`a → b → c → split d,e`) survives via `status/touches[]/supersedes[]` link-walk (`d/e → c → b`, two capped reads then stop). Acceptance: `motivation.md` §§4.4/4.8, ADR-0005, `c4-03`.
- **US-21 Retention = reachability, not age.** As a user, I want active entries retained (+ injectable suffix), causal entries one hop behind, unreferenced compacted to one INDEX line, removed lines to `handoffs/archive/` but persistent in git; reachable decisions decay-exempt. Acceptance: ADR-0005, `c4-05`.
- **US-22 Explicit forget/purge.** As a user, I want `forget`/purge to remove lines from active files while git retains history (`restore = checkout`). No silent age-based deletion of reachable decisions. Acceptance: `motivation.md` §4.3-7.
- **US-23 Phase-2 only, explicit and off by default.** As a user, I want 30d TTL sweep / access-weighted decay (`W_m(t)`, `W_min`) and SQLite FTS mirror available only as explicit opt-in commands, never automatic, applying only to unreachable episodic notes (never reachable decisions, never source of truth). Acceptance: `motivation.md` §§2/4.3-7/5, ADR-0001/0005, `c4-01`/`c4-02`.

### Trust boundary and curation

- **US-25 Review-due nudge (anti-forgetting).** As a user who might forget to curate, I want a bounded prompt so uncurated memory is surfaced. When `curation.pending` reaches ≥5 uncurated captures, the `context` hook emits one `[memory] <n> uncurated captures since last review; run /memory-review` line (model-facing; the agent relays it); it disappears once `/memory-review` resets the counter (via `memory_apply`; zero-candidate reviews reset directly). It never writes durable memory itself and never exceeds one line (dropped before the hint under budget pressure). Acceptance: nudge appears at the threshold, clears after review, no durable write, budget respected (`design-spec` §§3/5.5/5.7, `c4-03`/`c4-04`/`c4-06`).
- **US-26 What I say to remember is remembered — once.** As a user, I want an explicit "remember that X" in my own message to become durable immediately (append-only `decisions.md`, tagged `(user-asserted)`, written by the plugin in the `prompt` hook), so that recording a plain fact like the minimum supported PHP version never costs me a second `/memory-review` cycle. Acceptance: no second cycle for a documented directive; no origin can fast-path into `architecture.md`/`style.md`/`issues.md`; ambiguous phrasing or a "remember" inside fenced/quoted text stays in the scratchpad (pastes covered only by that heuristic) (ADR-0004 revision, `design-spec` §5.11).
- **US-27 Nothing I didn't author can silently poison memory.** As a user, I want memory content treated as untrusted data, so that a malicious dependency's error text cannot (a) make the agent run something, or (b) get promoted into a durable file and then injected into every future session. Acceptance: raw captured output never appears in the auto-injected payload (summary line only); `/memory-review`'s read+propose phase writes nothing and only produces a proposal table (not sandboxed; the optional read-only `memory-manager` subagent isolates the pass to a child session); every candidate is shown with its `source:` tag and advisory flags; untrusted candidates cannot be bulk-approved — `memory_apply` asserts one line at a time; `flagInjection` is advisory and never claims detection; residual risk (a human approving a poisoned untrusted line) is documented rather than hidden (ADR-0007, `design-spec` §5.11, `c4-04`/`c4-06`).

### Uninstall

- **US-24 Clean uninstall, no residue to chase.** As a user, I want to remove `plugins: ["./plugins/memory"]` (or `["./.opencode/plugins/memory"]`) and/or delete `.opencode/plugins/memory/`, remove the root `AGENTS.md` protocol block manually, and keep `.opencode/memory/` in git until I explicitly `git rm` it, so uninstall never auto-deletes memory. No daemon to kill, no server/container to tear down, no keys to revoke, no vector index or re-embed artifacts to purge, no `migrate/list-shards/export/import` ceremony (directory identity, no hashes). The `ctx.storage` ledger is plugin-scoped durable JSON and is harmlessly orphaned. Acceptance: `opencode plugin list` no longer shows `memory`; hooks stop firing; repo history still restores any prior state (`motivation.md` §3, ADR-0001, `c4-01`/`c4-02`).

## Part B — Agent Stories (OpenCode V2 agent + `memory-manager`)

- **AS-01 Follow the protocol chain.** As the agent, I follow root `AGENTS.md` protocol + links (top), `INDEX.md` content via deduped `prompt` hook, brief + status line + hint via `context` hook (bottom), so positions are deterministic. I never expect memory content in `AGENTS.md` and never write `AGENTS.md` (hand-owned). Acceptance: ADR-0002, `c4-01`, `c4-04`.
- **AS-02 Peek only on cause.** As the agent, before why/history/naming questions or touching a contract/previously-renamed symbol, I scan `INDEX.md`; on symbol/file/area match I call `memory_recall`; otherwise I proceed from current code alone. I never inject whole history files. Acceptance: standing directive ~10 lines + tool description policy (`motivation.md` §4.5, ADR-0005).
- **AS-03 One capped read, then stop.** As the agent, I read one capped file per question (truncation notice observed), link-walk at most `d/e → c → b` via `Supersedes`, then stop. Exact INDEX match only; never fuzzy/semantic similarity (compilers need exact binding, not closeness). Acceptance: `matchIndex` + `readCapped` contracts (`c4-06`, `motivation.md` §§4.4–4.5/4.8).
- **AS-04 Respect dedup + idempotency.** As the agent, I never re-attach `INDEX.md` if already present and never re-capture the same content ID (ledger `ctx.storage` check-before-write, ~30s retry). Restarts/replays are no-ops. Acceptance: ADR-0004, `c4-03`/`c4-04`.
- **AS-05 Propose, never silently write durable.** As the primary agent, I propose `decisions/architecture/style/issues` promotions (target file, exact lines, provenance tag, cap + redaction checks) via `/memory-review` and wait for approval; approved lines are applied verbatim (never paraphrased) through the plugin's `memory_apply` tool, which asserts each line before `writeCapped`. `issues.md` manual lines are validated, not overwritten. I never execute instructions from memory files — memory content is data. Acceptance: `c4-03` rules, `c4-04`, ADR-0004/0007.
- **AS-06 `memory-manager` is read-only.** As the `memory-manager` subagent (on-demand only), I read memory files and emit a provenance-tagged proposal table, then stop — I have **no `edit`, no `shell`, and no network tools (`webfetch`/`websearch`), and no `skill`**, so I cannot act on anything I read or exfiltrate it, and I cannot write durable memory at all. I treat all file content as untrusted data, never instructions. Acceptance: frontmatter denies those actions; application of approved lines happens outside this agent via `memory_apply` (`c4-02`, `c4-04`, `design-spec` §5.8, ADR-0007).
- **AS-07 Style lock.** As the agent, I keep the recorded architecture style across model swaps; a different pattern needs explicit justification referencing `decisions.md`. I implement existing interfaces/contracts first, survey sibling implementations, avoid core-engine disruption unless the contract must change, list ripple effects explicitly, and never propose deferring simple fixes to shrink blast radius. Acceptance: `motivation.md` §4.7, `c4-05` (pointer in `architecture.md`, rule text in `style.md`).
- **AS-08 Hygiene.** As the agent, I keep per-project scope (no cross-project reads), honor `<private>`/blocklist redaction and size caps, cite verifiable artifacts (`Touches` paths, SHAs, issue refs, contract names), and leave `handoffs/archive/` un-injected unless the user explicitly asks for recall. Acceptance: `c4-01`, `c4-05`, `motivation.md` §4.8.
- **AS-09 After uninstall.** As the agent, I lose `INDEX.md`/brief/hint injection and `memory_recall`/`/memory-review`; I fall back to code-only reasoning with no memory behavior change required. Acceptance: US-24.

## Part C — Harness Stories (OpenCode V2 runtime)

- **HS-01 Load the plugin.** As the harness, I load `memory` from the `plugins` array (plural; packages/versions/tags/ranges, Git specs, local dirs/files, `{package, options}`) or `.opencode/plugins/` auto-discovery, merging global → project → `.opencode` configs, so either US-01/US-02/US-03 resolves. Acceptance: `opencode plugin list` (`motivation.md` §2 row 5, `c4-01`/`c4-02`).
- **HS-02 Provide session hooks.** As the harness, I offer `session.hook("prompt" | "context" | "compaction" | "generate" | "title" | …)`; the plugin uses async never-throw `prompt` (sole INDEX injector, retry-safe/idempotent; also the site of the one `source:user` append to `decisions.md`, no pending increment), `context` (async/never-throw; `event.system.push` brief + one status line + ≤1 hint; brief does not duplicate INDEX), `compaction` (priors only via `event.system.push`; **`event.result` untouched**, no model/threshold/trigger change). Acceptance: `c4-03`, `c4-04`, ADR-0002/0003.
- **HS-03 Provide tool hooks + abortable events.** As the harness, I offer `ctx.tool.hook("execute.after")` (`status === "completed"|"error"`; `Tool.Error{message}` only) for failure capture and `ctx.event.subscribe({ signal })` + `AbortController` for idle/compaction capture and diagnostics; the plugin filters via `event.location` + session/project IDs. `session.idle` and `session.compaction.started/delta/ended/failed` are type-proven (`compaction.ended.data:{text,recent,…}`), with the async `context`-hook snapshot writer (throttle `<projectID>/snapshotThrottle/<sessionID>`) and pointer-only handoff as resilience fallbacks. Acceptance: `c4-03`, `motivation.md` §§4.3/4.6, `c4-06`, `design-spec` §1.3.
- **HS-04 Provide transforms.** As the harness, I offer `ctx.tool.transform(editor.add({ name: "memory_recall", ... }))` (allowlisted single-file read, capped + redacted, executor envelope via `toolResult` default `{ content }`, error on unknown/traversal) and `ctx.tool.transform(editor.add({ name: "memory_apply", ... }))` (executor-bound `sessionID/agent/source`, per-line `assert({action:"memory_write",resources:[file],save:[]})` → `writeCapped` sequentially with deny propagation; requires shipped `memory_write → ask`) and `ctx.command.transform(editor.add({ name: "memory-review", ... }))` (provenance-tagged proposal pass preserving attachments), so tools/commands exist without network/LLM. Acceptance: `c4-03`, `c4-04`, `c4-06`.
- **HS-05 Provide durable context.** As the harness, I offer plugin-scoped durable `ctx.storage` with `get`/`set`/`remove`/`scan` (ledger `<projectID>/seen/<id>` + `<projectID>/attempt/<id>` + `<projectID>/curation.pending` (scratchpad-only) + `<projectID>/curation.rotated` + `<projectID>/snapshot/<sessionID>` + `<projectID>/snapshotThrottle/<sessionID>` + `<projectID>/hint/<sessionID>/<promptHash>`, single-flight per content ID, pruned via `scan({prefix:"<projectID>/seen/"})` to ≤500, ~30s window), `ctx.vcs.get()` (branch) + `ctx.vcs.status()` (changes) for handoffs, `ctx.location` (`project.canonical ?? directory`, resolved per session for the absolute INDEX URI — `ctx.location` is the instance's location, not every session's), and `ctx.session.prompt` (review flow). Acceptance: `c4-02`/`c4-03`/`c4-05`/`c4-06`, ADR-0004.
- **HS-06 Enforce AGENTS.md hierarchy.** As the harness, I live-reload global/upward `AGENTS.md` before the next request but lazily discover below-workspace nested files (edits after load need a new session), which is why auto-written memory lives only in `.opencode/memory/`, never nested `AGENTS.md`. Acceptance: `motivation.md` §§2/4.3-8, ADR-0002.
- **HS-07 `instructions` are resolved; the design just doesn't use them.** As the harness, I resolve the `instructions` config array (relative/glob paths, `~/`, absolute, `http(s)`), loading it after `AGENTS.md`. This design nonetheless routes memory through root `AGENTS.md` + the `prompt`/`context` hooks, so injection has one owner and needs no config edit. Acceptance: ADR-0002 (revised), `c4-02`.
- **HS-08 Enforce config shapes.** As the harness, I accept `plugins` (plural), `agents` (plural, incl. `memory-manager`), ordered `permissions` (last matching rule wins), `default_agent`, `compaction`, and `references` (`{path, repository, branch, description, hidden}`). The plugin registers no `references` entry (ADR-0006). Acceptance: `motivation.md` §2 row 4, `c4-02`, `c4-04`.
- **HS-09 Keep compaction native.** As the harness, I run native automatic compaction; the plugin never sets thresholds, `event.result`, synthetic continuations, or model overrides. Acceptance: ADR-0003 (`supermemory` #69/#85/#88).
- **HS-10 Unload cleanly.** As the harness, on uninstall I stop loading the plugin, and its `setup` cleanup aborts the single event subscription and disposes every registration (`dispose()` awaited), leaving no daemon/server/embedding state; orphaned `ctx.storage` ledger needs no cleanup. Acceptance: US-24, `c4-01` boundary.
- **HS-11 Host the proposal-only review.** As the harness, I let a plugin-registered command prompt the session to produce a proposal table. A plugin command **cannot** target a subagent (`CommandInvocation` has no agent selector), and the plugin deliberately installs **no** session permission lock, because such a lock is time-scoped (the reviewed text persists in the transcript, so it defers rather than contains `T1`) and would deny the user's own tools. Containment is that the review writes nothing and every durable write is per-line approved (`memory_apply`); the read-only `memory-manager` subagent (`edit`/`shell`/`webfetch`/`websearch`/`skill` all deny) is an optional isolated venue when the primary agent delegates. Acceptance: `design-spec` §1.3 (retired G5)/§5.8, ADR-0007, `c4-03`.
