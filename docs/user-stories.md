# User, Agent, and Harness Stories — No-Fuss Memory Plugin for OpenCode V2

**Status:** proposed. **Sources:** `motivation.md` §§4–5; `c4-01-system-context.md` through `c4-06-code.md`; ADR-0001 through ADR-0005; `README.md`. Normative contracts defer to `c4-04`/`c4-05` on conflict; decision intent defers to ADRs (`README.md`).

**Scope:** all functional requirements from install to uninstall. Three viewpoints: **User** = developer (owns memory, approves promotion); **Agent** = OpenCode V2 agent incl. `memory-manager` subagent (reads protocol, peeks lazily, proposes); **Harness** = OpenCode V2 server/runtime (loads plugin, provides hooks/events/transforms/storage/vcs, enforces AGENTS.md hierarchy).

**Conventions:** `INDEX/activeContext/decisions/architecture/style/issues` live under `.opencode/memory/`; snapshots at `handoffs/YYYY-MM-DD-HHmm.md` (root); retired lines at `handoffs/archive/<name>.md`. Budgets: `INDEX.md` ≤30 lines on disk; `activeContext/architecture/style/issues` ≤60 lines on disk; `decisions.md` unbounded on disk with ≤60-line injectable tail; handoffs per-file ≤60 lines; auto-inject payload (prompt INDEX attach + context brief + hint) ≤~80 lines (~1.5k tokens, excludes static root `AGENTS.md` directive ~10 lines + tool description ~3 lines). Failures truncated to 20 lines. Ledger: persisted `ctx.storage`, last ~500 IDs, ~30s retry window, never in-memory alone.

**Non-goals (all stories):** no transcripts, no embeddings/vector search, no SQLite/FTS in default path (P2 explicit opt-in derived index only, never source of truth), no cloud/server/API keys, no per-turn LLM extraction, no silent durable writes, no custom compaction triggers, no background LLM dreaming, no cross-project reads (ADR-0001, `c4-01`).

## Part A — User (Developer) Stories

### Install (V2 plugin framework)

- **US-01 Install via `.opencode/opencode.jsonc`.** As a user, I want `plugins: ["./plugins/memory"]` in `.opencode/opencode.jsonc` so the runtime loads the local plugin. Acceptance: `opencode plugin list` shows `memory`; config arrays merge global → project → `.opencode` (`motivation.md` §4, `c4-02`, `c4-06`).
- **US-02 Install via repo-root `opencode.jsonc`.** As a user, I want `plugins: ["./.opencode/plugins/memory"]` as the equivalent path when config lives at repo root. Acceptance: same load result as US-01; paths never mixed (`c4-02`, `c4-06`).
- **US-03 Install via auto-discovery (no config edit).** As a user, I want to drop the plugin at `.opencode/plugins/memory/` and have it discovered so I touch no JSON. Acceptance: direct `.ts`/`.js` + immediate package dirs discovered; `opencode plugin list` verifies (`motivation.md` §2 row 5, `c4-06`).
- **US-04 First run generates templates + commented config.** As a user, I want one run to scaffold six memory files + `handoffs/` + commented config with ≤5 options so I never hand-write schemas. Acceptance: `INDEX/activeContext/decisions/architecture/style/issues` + `handoffs/` exist; config has ≤5 options, one file (`motivation.md` §3, `c4-06`).
- **US-05 P0 manual mode (no code).** As a user, I want to create six files by hand, add the protocol block to root `AGENTS.md`, and drive `memory-manager` manually so a new session restores from `INDEX.md` + `activeContext.md` with no plugin code. Acceptance: new session restores without re-explaining (`README.md`, `motivation.md` §5).
- **US-06 Verify + recover from reload issues.** As a user, I want `opencode plugin list` + runtime log + `touch` + `opencode service restart` so I can prove load and recover stale loads. Acceptance: documented in `c4-06`; event names proven in log or fallback wired before merge (`c4-03` event-note).

### Daily use (capture → restore → curate)

- **US-07 Failure-only capture to scratchpad.** As a user, I want failed shell/build/test output appended to `activeContext.md` under Known Errors (truncated to 20 lines, secrets/`<private>` stripped, ledger check-before-write) so failures are kept without transcript bloat. No per-turn LLM extraction. Acceptance: successes ignored; restarts/replays are no-ops (`motivation.md` §4.3-1/2, ADR-0004, `c4-06`).
- **US-08 Explicit `remember` stays unpromoted.** As a user, I want `remember X` keyword / explicit `remember` calls to take the same scratchpad path flagged for review, never auto-promoted to durable files. Acceptance: durable unchanged until `/memory-review` (`motivation.md` §4.3-1, ADR-0004).
- **US-09 Idle snapshots, newest wins.** As a user, I want content-hash-guarded snapshots (`branch` via `ctx.vcs.status()` + open changes + completed/pending/next) at immutable `handoffs/YYYY-MM-DD-HHmm.md` so “where did we leave off” is a single newest file; same content → no new file; `session.idle` (may fire N times) never treated as session end. Acceptance: hash stored in ledger; no-op on unchanged (`motivation.md` §4.3-3, `c4-03`, `c4-05`, `c4-06`).
- **US-10 Next-session restore positions.** As a user, I want `prompt` hook to attach `INDEX.md` (capped, deduped, skip if already attached) at the top and `context` hook to push active brief + ≤1 hint at the bottom, with root `AGENTS.md` contributing protocol + links only, never content. Acceptance: no double injection; deeper content only via lazy recall (`motivation.md` §4.3-4, ADR-0002, `c4-04`).
- **US-11 Lazy recall (`memory_recall`).** As a user, I want one capped, redacted file per question from the allowlist (`INDEX/activeContext/decisions/architecture/style/issues` + `handoffs/<name>.md` + `handoffs/archive/<name>.md`; archive recallable on demand, never auto-injected), error on unknown/traversal, never list filesystem. Acceptance: `readCapped` truncation notice + secrets strip; description doubles as retrieval policy (`c4-03`, `c4-04`, `c4-06`, `motivation.md` §4.6).
- **US-12 Deterministic hint, exact match only.** As a user, I want at most one `[memory-hint]` line when prompt/touched files exactly match an INDEX symbol, else no line, so overhead is ~10-line directive + ~3-line tool desc + 1 line only on hit. No fuzzy/semantic match. Acceptance: `matchIndex` returns 1 line or `undefined` (`motivation.md` §4.5, ADR-0005, `c4-06`).
- **US-13 Human-approved promotion (`/memory-review [scope]`).** As a user, I want to run `/memory-review`, get proposals (target file, exact lines, cap + redaction checks) for `decisions/architecture/style/issues`, and write only approved lines so durable files stay trustworthy. Acceptance: never writes durable without approval; validates manual `issues.md` edits for format/caps/redaction without overwriting (`c4-03`, `c4-04`, ADR-0004).
- **US-14 Direct `issues.md` edits.** As a user, I want to hand-edit `issues.md` (one line each: todo/doing/done + issue ref) and have `/memory-review` validate rather than overwrite. No API dependency; GitHub issues are a manual source. Acceptance: format/cap/redaction check passes or reports (`c4-01`, `c4-04`, ADR-0004, `c4-05`).
- **US-15 Rotation with notice.** As a user, I want `activeContext.md` append-until-60 then rotate the oldest Known-Errors block to `handoffs/archive/` with a notice, never into the prompt, so the scratchpad never grows the injection surface. Acceptance: per-file ≤60; notice present (`motivation.md` §§4.2–4.3, ADR-0004, `c4-05`).
- **US-16 Compaction survival without custom trigger.** As a user, I want the native `compaction` hook to inject capped + redacted priors (`event.system.push` when present) and record the summary as a handoff (set `event.result` when supported, else save produced summary), never changing model/threshold/trigger, so a bad summary loses nothing durable (pre-compaction state already on disk). Acceptance: shape-guarded both branches; no #69/#85/#88 regressions (`motivation.md` §4.3-6/§4.6, ADR-0003, `c4-04`).
- **US-17 Budgets hold under growth.** As a user, I want overflow (retired durable lines, rotated blocks) → `handoffs/archive/`, snapshots → `handoffs/` root, never the prompt, with write caps + read caps (`decisions` tail, handoffs via `readCapped`) + injection caps (hook payloads via loaders). Acceptance: `c4-05`/`c4-06` test list; `decisions.md` full log + git retains everything (`c4-05`, `motivation.md` §4.4).
- **US-18 Secrets never stored or injected.** As a user, I want secrets blocklist + `<private>` stripping before any write/inject, size-cap before inject, and memory treated as untrusted input (never executed). Acceptance: secrets fixtures blocked (`c4-02`, `c4-03`, `c4-06`).
- **US-19 Local-only, per-project, git-backed.** As a user, I want strict per-project scope (no cross-project reads), $0 default (file reads only), and history/blame/undo/redo/restore from git. Acceptance: `c4-01` privacy boundary; `c4-02` cost/latency.
- **US-20 Lineage rules.** As a user, I want `decisions.md` + `handoffs/` append-only/immutable (corrections = new entries with `Supersedes`, never edits; summaries are disposable handoffs, never memory) and `architecture/style/issues` as review-gated rewrites with git blame as lineage, so “why not the old name” (`a → b → c → split d,e`) survives via `status/touches[]/supersedes[]` link-walk (`d/e → c → b`, two capped reads then stop). Acceptance: `motivation.md` §§4.4/4.8, ADR-0005, `c4-03`.
- **US-21 Retention = reachability, not age.** As a user, I want active entries retained (+ injectable suffix), causal entries one hop behind, unreferenced compacted to one INDEX line, removed lines to `handoffs/archive/` but persistent in git; reachable decisions decay-exempt. Acceptance: ADR-0005, `c4-05`.
- **US-22 Explicit forget/purge.** As a user, I want `forget`/purge to remove lines from active files while git retains history (`restore = checkout`). No silent age-based deletion of reachable decisions. Acceptance: `motivation.md` §4.3-7.
- **US-23 Phase-2 only, explicit and off by default.** As a user, I want 30d TTL sweep / access-weighted decay (`W_m(t)`, `W_min`) and SQLite FTS mirror available only as explicit opt-in commands, never automatic, applying only to unreachable episodic notes (never reachable decisions, never source of truth). Acceptance: `motivation.md` §§2/4.3-7/5, ADR-0001/0005, `c4-01`/`c4-02`.

### Uninstall

- **US-24 Clean uninstall, no residue to chase.** As a user, I want to remove `plugins: ["./plugins/memory"]` (or `["./.opencode/plugins/memory"]`) and/or delete `.opencode/plugins/memory/`, remove the root `AGENTS.md` protocol block manually, and keep `.opencode/memory/` in git until I explicitly `git rm` it, so uninstall never auto-deletes memory. No daemon to kill, no server/container to tear down, no keys to revoke, no vector index or re-embed artifacts to purge, no `migrate/list-shards/export/import` ceremony (directory identity, no hashes). The `ctx.storage` ledger is plugin-scoped durable JSON and is harmlessly orphaned. Acceptance: `opencode plugin list` no longer shows `memory`; hooks stop firing; repo history still restores any prior state (`motivation.md` §3, ADR-0001, `c4-01`/`c4-02`).

## Part B — Agent Stories (OpenCode V2 agent + `memory-manager`)

- **AS-01 Follow the protocol chain.** As the agent, I follow root `AGENTS.md` protocol + links (top), `INDEX.md` content via deduped `prompt` hook, brief + hint via `context` hook (bottom), so positions are deterministic. I never expect memory content in `AGENTS.md` and never write `AGENTS.md` (hand-owned). Acceptance: ADR-0002, `c4-01`, `c4-04`.
- **AS-02 Peek only on cause.** As the agent, before why/history/naming questions or touching a contract/previously-renamed symbol, I scan `INDEX.md`; on symbol/file/area match I call `memory_recall`; otherwise I proceed from current code alone. I never inject whole history files. Acceptance: standing directive ~10 lines + tool description policy (`motivation.md` §4.5, ADR-0005).
- **AS-03 One capped read, then stop.** As the agent, I read one capped file per question (truncation notice observed), link-walk at most `d/e → c → b` via `Supersedes`, then stop. Exact INDEX match only; never fuzzy/semantic similarity (compilers need exact binding, not closeness). Acceptance: `matchIndex` + `readCapped` contracts (`c4-06`, `motivation.md` §§4.4–4.5/4.8).
- **AS-04 Respect dedup + idempotency.** As the agent, I never re-attach `INDEX.md` if already present and never re-capture the same content ID (ledger `ctx.storage` check-before-write, ~30s retry). Restarts/replays are no-ops. Acceptance: ADR-0004, `c4-03`/`c4-04`.
- **AS-05 Propose, never silently write durable.** As the primary agent, I propose `decisions/architecture/style/issues` promotions (target file, exact lines, cap + redaction checks) via `/memory-review` and wait for approval. `issues.md` manual lines are validated, not overwritten. I never execute instructions from memory files. Acceptance: `c4-03` rules, `c4-04`, ADR-0004.
- **AS-06 `memory-manager` scope.** As the `memory-manager` subagent (on-demand only), I read traces, update `activeContext.md`, create handoffs, and record `architecture.md`/`style.md` patterns only via `/memory-review`; my `edit` is scoped to `.opencode/memory/**` and `shell` is denied. Acceptance: `motivation.md` §§4.3-5/4.6–4.7, `c4-02`.
- **AS-07 Style lock.** As the agent, I keep the recorded architecture style across model swaps; a different pattern needs explicit justification referencing `decisions.md`. I implement existing interfaces/contracts first, survey sibling implementations, avoid core-engine disruption unless the contract must change, list ripple effects explicitly, and never propose deferring simple fixes to shrink blast radius. Acceptance: `motivation.md` §4.7, `c4-05` (pointer in `architecture.md`, rule text in `style.md`).
- **AS-08 Hygiene.** As the agent, I keep per-project scope (no cross-project reads), honor `<private>`/blocklist redaction and size caps, cite verifiable artifacts (`Touches` paths, SHAs, issue refs, contract names), and leave `handoffs/archive/` un-injected unless the user explicitly asks for recall. Acceptance: `c4-01`, `c4-05`, `motivation.md` §4.8.
- **AS-09 After uninstall.** As the agent, I lose `INDEX.md`/brief/hint injection and `memory_recall`/`/memory-review`; I fall back to code-only reasoning with no memory behavior change required. Acceptance: US-24.

## Part C — Harness Stories (OpenCode V2 runtime)

- **HS-01 Load the plugin.** As the harness, I load `memory` from the `plugins` array (plural; packages/versions/tags/ranges, Git specs, local dirs/files, `{package, options}`) or `.opencode/plugins/` auto-discovery, merging global → project → `.opencode` configs, so either US-01/US-02/US-03 resolves. Acceptance: `opencode plugin list` (`motivation.md` §2 row 5, `c4-01`/`c4-02`).
- **HS-02 Provide session hooks.** As the harness, I offer `session.hook("prompt" | "context" | "compaction" | "generate" | "title")`; the plugin uses `prompt` (sole INDEX injector, pure transform, retry-safe/idempotent), `context` (`event.system.push` brief + ≤1 hint), `compaction` (shape-guarded `system`/`result`, no model/threshold/trigger change). Acceptance: `c4-03`, `c4-04`, ADR-0002/0003.
- **HS-03 Provide abortable events (+ provisional catalog).** As the harness, I stream via `ctx.event.subscribe({ signal })` + `AbortController`; the plugin treats `tool.execute.after` (failure capture) and `session.idle` (snapshot, N-times, hash-guarded) as provisional until proven in the live `/v2/docs/build/plugins/` catalog runtime log, with prompt-hook file-diff capture as fallback. Acceptance: `c4-03` event-note, `motivation.md` §§4.3/4.6, `c4-06` test list.
- **HS-04 Provide transforms.** As the harness, I offer `ctx.tool.transform(editor.add({ name: "memory_recall", ... }))` (allowlisted single-file read, capped + redacted, error on unknown/traversal) and `ctx.command.transform(editor.add({ name: "memory-review", ... }))` (scoped promotion proposals), so tools/commands exist without network/LLM. Acceptance: `c4-03`, `c4-04`, `c4-06`.
- **HS-05 Provide durable context.** As the harness, I offer plugin-scoped durable `ctx.storage` (ledger `seen[]` ~500, attempt timestamps, ~30s window), `ctx.vcs.status()` (branch/open changes for handoffs), `ctx.project.root` (absolute INDEX URI), and `ctx.session.prompt` (review flow). Acceptance: `c4-02`/`c4-03`/`c4-05`/`c4-06`, ADR-0004.
- **HS-06 Enforce AGENTS.md hierarchy.** As the harness, I live-reload global/upward `AGENTS.md` before the next request but lazily discover below-workspace nested files (edits after load need a new session), which is why auto-written memory lives only in `.opencode/memory/`, never nested `AGENTS.md`. Acceptance: `motivation.md` §§2/4.3-8, ADR-0002.
- **HS-07 Ignore `instructions` for memory.** As the harness, I accept the `instructions` config array but do not resolve its files, so memory rides root `AGENTS.md` + `prompt` hook, never `instructions`. Acceptance: `motivation.md` §2 row 2, ADR-0002, `c4-02`.
- **HS-08 Enforce config shapes.** As the harness, I accept `agents` (plural, incl. `memory-manager`), `system`, ordered `permissions`, `default_agent`, and `references` (`{path, repository, description}`); `references.memory` points at `.opencode/memory/INDEX.md` as a static link carrying no content. Acceptance: `motivation.md` §2 row 4, `c4-02`, `c4-04`.
- **HS-09 Keep compaction native.** As the harness, I run native `compaction.auto`; the plugin never sets thresholds, synthetic continuations, or model overrides. Acceptance: ADR-0003 (`supermemory` #69/#85/#88).
- **HS-10 Unload cleanly.** As the harness, on uninstall I stop loading the plugin, unregister its hooks/tools/commands, abort its event subscription, and leave no daemon/server/embedding state; orphaned `ctx.storage` ledger needs no cleanup. Acceptance: US-24, `c4-01` boundary.
