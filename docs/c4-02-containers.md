# C4 Level 2 — Containers / HLD: No-Fuss Memory Plugin for OpenCode V2

**Status:** proposed. **Sources:** Synthesized Report §4; V2 docs `/v2/docs/plugins/`, `/v2/docs/build/plugins/`, `/v2/docs/config/`. **Normative on V2 contracts:** `design-spec-v2-production.md`.

## Containers (all local, single machine)

| Container                            | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenCode TUI/CLI                     | Developer surface; runs `/memory-review` and prompts for per-line approval; the `[memory]` status notice is model-facing and relayed by the agent                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| OpenCode V2 server + plugin runtime  | Loads plugin from `plugins` array or `.opencode/plugins/` auto-discovery; exposes `session.hook`, `tool.hook`, `event.subscribe`, `tool`/`command` transforms, `storage`, `vcs`                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Memory file store                    | Six markdown files (`INDEX/activeContext/decisions/architecture/style/issues`) + `handoffs/` under the fixed directory `.opencode/memory/` (see `c4-05-data-model.md`; `handoffs/` root = session snapshots, `handoffs/archive/` = retired durable lines, rotated scratchpad blocks, and forgotten archives). All plugin writes share the cross-process `.write.lock` and atomic temp+rename/link publish (ADR-0010)                                                                                                                                                                                                  |
| Lifecycle commands                   | User-invoked `/memory-forget` and `/memory-gc` (dry-run by default; `--confirm` required; no model-facing delete tool). Forget archives before rewriting and rejects `decisions.md`/handoffs; GC targets root `handoffs/*.md` only and never archive (ADR-0009)                                                                                                                                                                                                                                                                                                                                                       |
| Capture ledger                       | Durable JSON in `ctx.storage` (`<projectID>/seen/<id>`, `<projectID>/attempt/<id>`, `<projectID>/curation.pending` (scratchpad-only), `<projectID>/curation.rotated`, `<projectID>/snapshot/<sessionID>` (`{hash, at}`), `<projectID>/snapshotThrottle/<sessionID>`, `<projectID>/hint/<sessionID>/<promptHash>`, `<projectID>/notice.indexOverCap` / `notice.captureFailed` / `notice.forgotten`; `ctx.storage` is plugin-scoped) — restart-safe idempotency with a single-flight (no CAS in the API); `seen` capped at 500 and aged attempts/hints/snapshot stamps pruned by the once-per-UTC-day housekeeping pass |
| `memory-manager` (optional)          | Read-only subagent (`edit`/`shell`/`webfetch`/`websearch`/`skill` deny) that reads memory and emits a provenance-tagged proposal table; it cannot act on what it reads (ADR-0007). Optional **isolated venue** for the review — a child session keeps poisoned text out of the user's transcript. The default review runs in-session and writes no memory (its only side effect is the ADR-0008/§5.12 `review.invoked` counter — count diagnostics, no content); there is **no** session permission lock (retired G5)                                                                                                 |
| Git repository                       | History, blame, restore; branch/status source for handoff snapshots                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| FTS mirror (deferred P2 opt-in only) | Read-only derived index, never source of truth; off by default per ADR-0001                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Topology and data flow

Single machine, zero network calls in the default path. Flow: prompt admission → INDEX attach (`prompt` hook async/never-throw, sole `INDEX.md` content injector, deduped) + the one `source:user` append to `decisions.md` (no pending increment) + the prompt-tail notice block (newest-handoff pointer, status line, ≤1 hint; ≤3 marker-guarded data-only lines) → work with failure-only capture (`tool.hook("execute.after")` → message-derived `source:tool` summary + optional recall-only detail in the scratchpad) → stable brief only (message-derived summary lines, max 5; never INDEX/tail/pointer) (`context` hook, async/never-throw; root AGENTS.md carries protocol+links only, never content) → content-hash-guarded idle snapshot (`session.idle`, `handoffs/YYYY-MM-DD-HHmmss-<session6>.md`; branch via `vcs.get()`, changes via `vcs.status()`; same content → no-op; newest wins; events filtered via `event.location`) → priors (activeContext + decisions tail + handoff) into summary (`compaction` hook, priors only — never sets `event.result`; produced summary captured from `compaction.ended` text+recent) → human-approved promotion (`/memory-review` writes no memory and returns a proposal table — its only side effect is the §5.12 `review.invoked` counter; the `memory_apply` tool approves one line per `ctx.permission.assert` and writes via `writeCapped`; `memory_apply` resets the status counters). Lifecycle is explicit: `/memory-forget` previews, takes per-unit approval, archives redacted text, then rewrites; `/memory-gc` previews root handoffs, takes one batch approval, re-plans under the lock, then deletes. Neither is a model-callable tool.

## Cross-cutting concerns

- **Budgets:** `INDEX.md` ≤30 lines on disk; `activeContext/architecture/style/issues` ≤60 lines on disk; `decisions.md` unbounded on disk with ≤60-line injectable tail via `loadPriors` + recall only (never the per-call brief; full log + git retains everything); root handoffs per-file ≤60 lines (archive writes are uncapped for preservation; archive reads are recall-capped). Injectable payload = `INDEX ≤30 + brief ≤47 (loader max 48; max 5 error lines) + prompt-tail notices ≤3 = ≤80`; static `AGENTS.md` + tool descriptions are 16 lines outside that cap. `INDEX` and the pointer/status/hint notices attach **once per prompt**; only the stable brief re-emits **per model call** (session-total 237 lines at 4 steps — an uncached line guardrail, not a billed-token claim). The hint is throttled via `<projectID>/hint/<sessionID>/<promptHash>`. Content overflow (retired lines, rotated scratchpad blocks, forgotten lines) → `handoffs/archive/`; session snapshots → `handoffs/` root; never the prompt. The status line carries the over-cap/oversize `INDEX` notice, rotation notice, skipped-capture notice, forgotten notice, and review-due nudge (≥5 uncurated scratchpad captures) so uncurated memory is surfaced. It is appended to the **prompt tail**, is model-facing, and delivery depends on the agent relaying it. `/memory-gc` deletes root handoffs only; archive is never purged.
- **Cost/latency:** $0 default; file reads only.
- **Permissions:** `memory-manager` subagent is **read-only** — `edit`/`shell`/`webfetch`/`websearch`/`skill` all `* → deny` (ADR-0007); it proposes and never writes, so application of approved lines happens outside it, through the plugin's `memory_apply` tool (`ctx.permission.assert` per line + `writeCapped`). The **default/primary** agent needs a `subagent` allow for `memory-manager` **only** if the optional delegation path is enabled. There is **no** session permission lock: the review only proposes and every write is per-line approved (retired G5).
- **Security:** secrets blocklist, `<private>` redaction, per-project isolation (root resolved per session from `event.location`; foreign events dropped), size caps before inject. Memory content is **untrusted data, never instructions**: raw captured output is never auto-injected (message-derived summary only), and untrusted candidates are never bulk-approved — `memory_apply` approves one line per `ctx.permission.assert` (ADR-0007). Forgetting is logical, not secure erasure: git history, backups, clones, and editor caches may retain removed text, so rotate exposed secrets (ADR-0009).
- **Config:** `.opencode/opencode.jsonc` → `plugins: ["./plugins/memory"]`; repo-root `opencode.jsonc` → `plugins: ["./.opencode/plugins/memory"]`; plus `agents: { memory-manager }`. Memory location is fixed at `.opencode/memory` (read-path choke point + recall allowlist, ADR-0006) and no `references` entry is registered (references attach directories and are client-initiated). V2 **does** resolve the `instructions` array, but the design routes memory through root `AGENTS.md` + the `prompt`/`context` hooks instead — a deliberate single-owner choice, not a platform limitation.
