### Design decisions (locked)

1. **Numbers only (ADR-0008).** Every persisted metrics value is a JSON number; keys come only from the enumerated vocabulary + the six structural file names + `handoff`/`error`/`arm·since` key shapes. No prompt text, tool output, captured paths, identities, or prose ever enters a metric. `redact` is deliberately NOT applied (nothing free-text is ever stored).
2. **Fail-closed vocabulary.** `METRIC_NAMES` is an exhaustive `ReadonlySet<string>` of the §5.12 table; `bump` logs + drops unknown names (never writes, never throws). Publishes name stability via tests.
3. **No sixth option.** `parseMemoryOptions` untouched (ADR-0006). Collection is always on; `/memory-metrics reset` is the control; uninstall orphans keys (US-29).
4. **Fire-and-forget bumps.** `bump(name, by=1): void` synchronously validates the name (throws nothing — misformat logs) and schedules ONE `withWriteLock` body that writes total + day pair (+ lazy `since` when absent), with its own `.catch(logDiagnostic)` equivalent. Bumps never await, never delay, never alter outcomes; loss on crash/cross-process is accepted (best-effort statistics, ADR-0008 §3). The arm flag is the exception: `setArm` is awaited at the hint-hit site (storing the arming timestamp — a positive int that arms for at most one UTC day), and the recall-side consumption runs through `consumeArm` — read + clear in ONE locked body, never-throw — because the subsequent `hint.recall` counter depends on it and concurrent recalls must count at most once.
5. **Type-only imports across `capture.ts` ↔ `metrics.ts`.** `metrics.ts` imports `LedgerStorage` type from `capture.ts`; `capture.ts` imports `MetricsBump` type from `metrics.ts`. Both erased at compile time — no runtime cycle; `capture.ts` receives its bump as an optional dep (undefined = silent no-op), preserving every existing signature/return type (verified by the untouched `test/ledger.test.ts` + `test/isolation.test.ts`).
6. **Deterministic renderer.** `renderMetricsDashboard(input)` is pure over `{ totals, days, health, since }`; sorted output; the only strings it can emit are counter names, structural file names, UTC day stamps, and integers. `health` is collected on request via `readFile` + `countLines` + ledger scans — file *bodies* are never emitted.
7. **Synthetic + G-M1 + fallback.** `/memory-metrics` (no arg) → compute → `await ctx.session.synthetic({ sessionID, text: table })` → bump `dashboard.shown`; log-once G-M1 line at the first post of the process: `[memory-metrics] synthetic posted (<session6>); confirm the table rendered without a model turn`. On reject → §5.5 fallback `ctx.session.prompt({ ...prompt, sessionID, delivery, text: METRICS_FALLBACK_ASK })` (agent calls `memory_metrics`, echoes verbatim). `reset` argument wipes all `<projectID>/metrics/…` keys + re-stamps `since`, then reports via the same channel. Executor never throws; final catch → `logDiagnostic`.
8. **`snapshotIfDue` keeps its boolean signature** — the bump happens inside from an `options.bump` tap on its internal outcome; `dispatchEvent` bumps outside the handlers via the deps tap. No return-type/contract changes anywhere (G-series contracts untouched).
