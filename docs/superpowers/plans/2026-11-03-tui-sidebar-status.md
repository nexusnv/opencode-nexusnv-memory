# TUI Sidebar Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only, project-scoped memory status line to the OpenCode TUI `sidebar.footer`, backed by one typed RPC that returns `{ state, pending }` and never writes or consumes anything.

**Architecture:** The existing server plugin gains a pure snapshot module (`src/sidebar.ts`), a read-only collector plus RPC registration (`src/sidebar-status.ts`), and a shared RPC contract (`src/rpc.ts`). A second TUI plugin part (`src/tui.tsx`, exported at `./tui`) parses one presentation-only option, claims `sidebar.footer`, polls the RPC every 5 seconds with a 4-second timeout, and hides the line on any failure. The server keeps its five-option contract and its initialization gate; the collector checks `isInitialized` before any storage read.

**Tech Stack:** TypeScript 5.9 (`strict`, `nodenext`, `es2022`), `@opencode/plugin` 2.0.29 (Promise + TUI flavors), `@opencode/theme` 2.0.29 types, `@opentui/core` 0.5.17, `@opentui/solid` 0.5.17, `solid-js` 1.9.12, Vitest 5, Node 20+ for the server plugin; the TUI part requires Bun ≥1.3 or Node ≥26.4 with --experimental-ffi (@opentui/core 0.5.17 requirement).

 * Shared read-only RPC contract for the TUI sidebar status indicator.
 *
 * The server half registers the handler under `nexusnv.memory`; the TUI half

import { Rpc } from "@opencode/plugin/rpc";

export const MEMORY_RPC_ID = "nexusnv.memory";

export const MemoryRpc = Rpc.define({
  id: MEMORY_RPC_ID,
  methods: {
    sidebarStatus: {
      input: {
        type: "object",
        properties: {},
        required: [],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: {
          state: {
            type: "string",
            enum: ["not-initialized", "healthy", "pending", "attention"],
          },
          pending: { type: "integer", minimum: 0 },
        },
        required: ["state", "pending"],
        additionalProperties: false,
      },
    },
  },
  events: {},
});

```ts
/**
 * Pure TUI sidebar state (ADR-0012, spec §5.15).
 *
 * No fs, storage, Solid, or theme imports: the server collector, the TUI
 * component, and the unit tests all share these functions without pulling a
 * runtime into the wrong process.
 */
import type { WarnFn } from "./config.js";

export type SidebarState =
  | "not-initialized"
  | "healthy"
  | "pending"
  | "attention";

export interface SidebarFacts {
  readonly initialized: boolean;
  /**
   * True only when INDEX was read after initialization and its line count is
   * within the cap. False for missing, unreadable, over-cap, or too-large
   * INDEX files.
   */
  readonly indexWithinCap: boolean;
  readonly overCapNotices: number;
  readonly stalePointers: number;
  readonly failedCaptures: number;
  readonly pending: number;
}

export interface SidebarSnapshot {
  readonly state: SidebarState;
  readonly pending: number;
}

export interface SidebarOptions {
  readonly showSidebarStatus: boolean;
}

export const DEFAULT_SIDEBAR_OPTIONS: SidebarOptions = {
  showSidebarStatus: true,
};

export type SidebarTone = "warning" | "error" | "success";

export interface SidebarLabel {
  readonly text: string;
  readonly tone: SidebarTone;
}

const SIDEBAR_STATES: ReadonlySet<string> = new Set([
  "not-initialized",
  "healthy",
  "pending",
  "attention",
]);

/** Keys already warned about in this process; each invalid key warns once. */
const warnedKeys = new Set<string>();

/** Test seam: clear warn-once state between assertions. */
export function resetSidebarOptionsWarnings(): void {
  warnedKeys.clear();
}

function warnOnce(key: string, warn: WarnFn, message: string): void {
  if (warnedKeys.has(key)) return;
  warnedKeys.add(key);
  try {
    warn(message);
  } catch {
    // A failing logger must never break TUI load.
  }
}

/**
 * Parse the TUI-only visibility option. Never throws. Non-object input is
 * silent because the server parser already warns for the same malformed
 * `ctx.options` value; only `showSidebarStatus` itself warns here.
 */
export function parseSidebarOptions(
  raw: unknown,
  warn: WarnFn = console.warn,
): SidebarOptions {
  try {
    if (typeof raw !== "object" || raw === null) {
      return { ...DEFAULT_SIDEBAR_OPTIONS };
    }
    const value = (raw as Record<string, unknown>)["showSidebarStatus"];
    if (value === undefined) return { ...DEFAULT_SIDEBAR_OPTIONS };
    if (typeof value !== "boolean") {
      warnOnce(
        "showSidebarStatus",
        warn,
        `[memory] invalid option showSidebarStatus=${JSON.stringify(value)}; using default true`,
      );
      return { ...DEFAULT_SIDEBAR_OPTIONS };
    }
    return { showSidebarStatus: value };
  } catch {
    return { ...DEFAULT_SIDEBAR_OPTIONS };
  }
}

/**
 * Fixed precedence: not-initialized > attention > pending > healthy.
 * The not-initialized branch reports pending 0 because the collector did not
 * read storage; attention and pending carry the observed counter.
 */
export function deriveSidebarSnapshot(facts: SidebarFacts): SidebarSnapshot {
  if (!facts.initialized) {
    return { state: "not-initialized", pending: 0 };
  }
  if (!facts.indexWithinCap) {
    return { state: "attention", pending: facts.pending };
  }
  if (
    facts.overCapNotices > 0 ||
    facts.stalePointers > 0 ||
    facts.failedCaptures > 0
  ) {
    return { state: "attention", pending: facts.pending };
  }
  if (facts.pending > 0) {
    return { state: "pending", pending: facts.pending };
  }
  return { state: "healthy", pending: 0 };
}

/** One fixed label per state; the pending count appears only in `pending`. */
export function renderSidebarLabel(snapshot: SidebarSnapshot): SidebarLabel {
  switch (snapshot.state) {
    case "not-initialized":
      return { text: "○ memory · run /memory-init", tone: "warning" };
    case "attention":
      return { text: "▲ memory · needs attention", tone: "error" };
    case "pending":
      return {
        text: `◐ memory · ${snapshot.pending} pending`,
        tone: "warning",
      };
    case "healthy":
      return { text: "● memory · healthy", tone: "success" };
  }
}

/**
 * Validate the portable RPC result at the TUI boundary. The client return type
 * is `unknown`, so an invalid or foreign payload must hide the line rather
 * than reach the renderer.
 */
export function isSidebarSnapshot(value: unknown): value is SidebarSnapshot {
  if (typeof value !== "object" || value === null) return false;
  const snapshot = value as Record<string, unknown>;
  const state = snapshot["state"];
  const pending = snapshot["pending"];
  return (
    typeof state === "string" &&
    SIDEBAR_STATES.has(state) &&
    typeof pending === "number" &&
    Number.isInteger(pending) &&
    pending >= 0
  );
}
```

  }
  async remove(key: string): Promise<void> {
    this.removes.push(key);
    this.data.delete(key);
  }
  async scan(options: {
    prefix: string;
    after?: string;
    limit?: number;
  }): Promise<{
    entries: Array<{ key: string; value: unknown }>;
    next?: string;
  }> {
    let keys = [...this.data.keys()]
      .filter((key) => key.startsWith(options.prefix))
      .sort();
    if (options.after !== undefined) {
      keys = keys.filter((key) => key > options.after!);
    }
    const page = keys.slice(0, options.limit ?? 100);
    return {
      entries: page.map((key) => ({ key, value: this.data.get(key) })),
      next:
        page.length > 0 && keys.length > page.length
          ? page[page.length - 1]
          : undefined,
    };
  }
}

/**
 * Server-side sidebar status collector and RPC registration (ADR-0012).
 *
 * Read-only by construction: the collector checks initialization first and
 * returns the pre-init reminder without a storage read. For an initialized
 * project it reads the existing INDEX line count, pending counter, and three
 * actionable notice markers through `get` only — it never calls `set`,
 * `remove`, `takeNotice`, `takeRotated`, or a metric bump.
 */
import type { Plugin } from "@opencode/plugin";
import { join } from "node:path";
import { indexLineCount } from "./brief.js";
import {
  getNotice,
  getPending,
  type LedgerStorage,
  type NoticeKind,
} from "./capture.js";
import {
  asLedger,
  memoryRootOf,
  projectIDOf,
} from "./command-context.js";
import { isInitialized } from "./init.js";
import { MemoryRpc } from "./rpc.js";
import { deriveSidebarSnapshot, type SidebarSnapshot } from "./sidebar.js";

export interface SidebarStatusInput {
  readonly memoryRoot: string;
  readonly storage: LedgerStorage;
  readonly projectID: string;
  readonly indexLines: number;
}

export interface SidebarStatusDeps {
  readonly isInitialized: (memoryRoot: string) => Promise<boolean>;
  readonly indexLineCount: (
    absPath: string,
    memoryRoot: string,
    indexLines: number,
  ) => Promise<number | undefined>;
  readonly getPending: (
    storage: LedgerStorage,
    projectID: string,
  ) => Promise<number>;
  readonly getNotice: (
    storage: LedgerStorage,
    projectID: string,
    kind: NoticeKind,
  ) => Promise<number | undefined>;
}

const defaultDeps: SidebarStatusDeps = {
  isInitialized,
  indexLineCount,
  getPending,
  getNotice,
};

export async function collectSidebarStatus(
  input: SidebarStatusInput,
  deps: SidebarStatusDeps = defaultDeps,
): Promise<SidebarSnapshot> {
  if (!(await deps.isInitialized(input.memoryRoot))) {
    return { state: "not-initialized", pending: 0 };
  }

  const indexCount = await deps.indexLineCount(
    join(input.memoryRoot, "INDEX.md"),
    input.memoryRoot,
    input.indexLines,
  );
  const [pending, overCapNotices, stalePointers, failedCaptures] =
    await Promise.all([
      deps.getPending(input.storage, input.projectID),
      deps.getNotice(input.storage, input.projectID, "indexOverCap"),
      deps.getNotice(input.storage, input.projectID, "indexStale"),
      deps.getNotice(input.storage, input.projectID, "captureFailed"),
    ]);

  return deriveSidebarSnapshot({
    initialized: true,
    indexWithinCap:
      indexCount !== undefined && indexCount <= input.indexLines,
    overCapNotices: overCapNotices ?? 0,
    stalePointers: stalePointers ?? 0,
    failedCaptures: failedCaptures ?? 0,
    pending,
  });
}

/**
 * Register the read-only RPC unconditionally. The method must answer before
 * and after initialization, and the TUI is a separate plugin part; guarding
 * registration would silently drop the indicator instead of failing the host
 * contract.
 */
export function registerSidebarRpc(
  ctx: Plugin.Context,
  indexLines: number,
) {
  const storage = asLedger(ctx.storage);
  const projectID = projectIDOf(ctx);
  const memoryRoot = memoryRootOf(ctx);
  return ctx.rpc.register(MemoryRpc, {
    sidebarStatus: async () =>
      collectSidebarStatus({ memoryRoot, storage, projectID, indexLines }),
  });
}

/**
 * TUI half of the memory plugin (ADR-0012).
 *
 * Claims exactly one additive `sidebar.footer` line. The component never reads
 * memory files or `ctx.storage`; it asks the server half for a bounded
 * `{ state, pending }` snapshot through the typed RPC and hides the line on
 * any failure. `showSidebarStatus: false` registers nothing at all.
 */
import type { Context } from "@opencode/plugin/tui/context";
import { Plugin } from "@opencode/plugin/tui";
import type { RGBA } from "@opentui/core";
import { Show, createSignal, onCleanup, onMount } from "solid-js";
import { MemoryRpc } from "./rpc.js";
import {
  isSidebarSnapshot,
  parseSidebarOptions,
  renderSidebarLabel,
  type SidebarSnapshot,
  type SidebarTone,
} from "./sidebar.js";

const POLL_INTERVAL_MS = 5_000;
const REQUEST_TIMEOUT_MS = 4_000;

function toneColor(context: Context, tone: SidebarTone): RGBA {
  switch (tone) {
    case "error":
      return context.theme.text.feedback.error.base;
    case "warning":
      return context.theme.text.feedback.warning.base;
    case "success":
      return context.theme.text.feedback.success.base;
  }
}

export function MemoryStatusLine(props: { readonly context: Context }) {
  const [snapshot, setSnapshot] = createSignal<SidebarSnapshot>();
  let disposed = false;
  let inFlight: AbortController | undefined;

  async function refresh(): Promise<void> {
    if (disposed || inFlight) return;
    const controller = new AbortController();
    inFlight = controller;
    const timeout = setTimeout(() => {
      controller.abort();
      // Recover even if the client never settles the aborted request; a late
      // result is ignored by the aborted check below.
      if (inFlight === controller) inFlight = undefined;
    }, REQUEST_TIMEOUT_MS);

    try {
      const location =
        props.context.location ?? props.context.data.location.default();
      const result = await props.context.client
        .rpc(MemoryRpc)
        .sidebarStatus({}, { location, signal: controller.signal });
      if (disposed || controller.signal.aborted) return;
      setSnapshot(isSidebarSnapshot(result) ? result : undefined);
    } catch {
      if (!disposed) setSnapshot(undefined);
    } finally {
      clearTimeout(timeout);
      if (inFlight === controller) inFlight = undefined;
    }
  }

  onMount(() => {
    void refresh();
    const timer = setInterval(() => {
      void refresh();
    }, POLL_INTERVAL_MS);
    const offSynthetic = props.context.data.on("session.synthetic", () => {
      void refresh();
    });
    const offIdle = props.context.data.on("session.idle", () => {
      void refresh();
    });

    onCleanup(() => {
      disposed = true;
      clearInterval(timer);
      inFlight?.abort();
      offSynthetic();
      offIdle();
    });
  });

  return (
    <Show when={snapshot()}>
      {(current) => {
        const label = () => renderSidebarLabel(current());
        return (
          <text
            fg={toneColor(props.context, label().tone)}
            wrapMode="none"
            truncate
          >
            {label().text}
          </text>
        );
      }}
    </Show>
  );
}

export default Plugin.define({
  id: "memory.tui",
  setup(context) {
    if (!parseSidebarOptions(context.options).showSidebarStatus) return;
    const unregister = context.ui.slot({
      append: "sidebar.footer",
      render: () => <MemoryStatusLine context={context} />,
    });
    return () => unregister();
  },
});

## Context

Issue #29 asks for a minimal, always-visible memory status in the OpenCode TUI. The plugin already
exposes `/memory-status`, but a command must be invoked. The TUI publishes a `sidebar.footer` slot
and a typed, location-scoped RPC, so one passive line can show installed, healthy, pending, or
attention without creating a second source of truth. The line must not become the rich metrics
panel deferred by ADR-0008, and it must not weaken the initialization gate in ADR-0011.

## Decision

- Ship a second plugin part, `memory.tui`, exported at `./tui`. It appends exactly one line to
  `sidebar.footer` and never wraps, expands, or replaces other content.
- The TUI never reads memory files or `ctx.storage`. It calls one read-only RPC,
  `nexusnv.memory.sidebarStatus`, registered unconditionally by the server part. The method accepts
  no input and returns only `{ state, pending }`.
- The server collector checks `isInitialized` first. An uninitialized project returns
  `{ state: "not-initialized", pending: 0 }` without a storage read, so the `/memory-init` reminder
  survives a storage outage. For an initialized project the collector reads the existing INDEX line
  count, pending counter, and three unconsumed notice markers. It never calls `set`/`remove`, never
  consumes a notice, and never bumps a metric.
- Four states with fixed precedence: `not-initialized` > `attention` > `pending` > `healthy`.
  `attention` covers an uninspectable or over-cap INDEX and an unconsumed `indexOverCap`,
  `indexStale`, or `captureFailed` notice. `pending` means `pending > 0`; the prompt review-due
  threshold stays at 5.
- Visibility is a TUI-only option, `showSidebarStatus` (default `true`). `false` registers no slot,
  starts no poll, and makes no RPC call. An invalid value warns once and stays visible.
- Fail closed: a rejected, invalid, transport-failed, or timed-out (4 s) snapshot clears the line.
  Polling resumes on a later successful call; the in-flight guard clears in `finally` and on timeout.
  A late response after unmount is ignored.
- The indicator adds no storage key, memory file, metric name, model-facing tool, or server behavior
  option.

## Consequences

- Positive: pre-init discovery improves without a command, and install health is visible at a glance.
  The server remains the only reader, so the TUI cannot leak or corrupt memory state.
- Negative: one read-only RPC per mounted footer every 5 seconds, and the line is project-wide rather
  than per-session. Notices remain consumable by the prompt status line, so `attention` can clear when
  the model reports the same condition; the sidebar is a read-only mirror, not the actionable report.
- The rich metrics panel stays deferred (ADR-0008). The server option contract stays at exactly five;
  only the TUI parser reads `showSidebarStatus`.
```

### 5.15 TUI sidebar status indicator (US-33, HS-15, ADR-0012)

**Purpose.** One passive, project-scoped line in `sidebar.footer` answers "is memory installed,
healthy, waiting for review, or in need of attention?" without invoking a command. It is **not** the
deferred rich metrics panel (§8 D-G, ADR-0008): it has four fixed states, no page, no router, no
interaction, and no metrics.

**Surface.** A second plugin part (`./tui`, id `memory.tui`) claims `sidebar.footer` with one additive
line. The server part registers one read-only RPC, `nexusnv.memory.sidebarStatus`, unconditionally so
it answers before and after initialization. The RPC accepts no input and returns exactly
`{ state: "not-initialized" | "healthy" | "pending" | "attention", pending: integer >= 0 }`.

**States and precedence.** `not-initialized` > `attention` > `pending` > `healthy`.

| State | Condition | Label | Theme token |
| --- | --- | --- | --- |
| `not-initialized` | `.opencode/memory/INDEX.md` is not an existing regular file. | `○ memory · run /memory-init` | `text.feedback.warning.base` |
| `attention` | Initialized, and INDEX is uninspectable/over-cap or an unconsumed `indexOverCap`, `indexStale`, or `captureFailed` notice is positive. | `▲ memory · needs attention` | `text.feedback.error.base` |
| `pending` | Initialized, no attention condition, and `curation.pending > 0`. | `◐ memory · {n} pending` | `text.feedback.warning.base` |
| `healthy` | Initialized, INDEX within cap and inspectable, no actionable notice, pending zero. | `● memory · healthy` | `text.feedback.success.base` |

`forgotten` and `rotated` notices are informational and do not produce `attention`. The prompt
review-due nudge stays at `pending >= 5`; the sidebar adds no second threshold.

**Read path and pre-init short-circuit.** The collector checks `isInitialized()` first. When false it
returns `not-initialized` with pending `0` **without reading storage**, so a storage outage cannot hide
the `/memory-init` reminder. For an initialized project it reads the existing `indexLineCount` result
(`undefined` for missing/unreadable; `indexLines + 1` when the line or byte cap is hit), `getPending`,
and three unconsumed `getNotice` values. A missing/unreadable INDEX or a count above `indexLines` is
`attention`.

**Side-effect guarantees.** The collector never calls `set`/`remove`, never calls
`takeNotice`/`takeRotated`, never bumps a metric, never writes a memory file, and never consumes a
notice. It adds no storage key, file, metric name, model-facing tool, or server behavior option. The
prompt status line remains the actionable report; the sidebar is a read-only mirror, so `attention`
can clear once the model reports the same condition.

**Visibility.** `showSidebarStatus` defaults to `true` and is parsed only by the TUI part. `false`
registers no slot, starts no polling, and makes no RPC call. Any other value warns once and stays
visible. The server still parses exactly the five behavior options; `parseMemoryOptions` ignores this
unknown key.

**Failure behavior.** A rejected handler, transport failure, invalid payload, or request exceeding a
4-second timeout clears the rendered snapshot and hides the line. The in-flight guard clears in
`finally` and on timeout, so a stalled request cannot disable later polls; late responses after
unmount are ignored. The TUI never shows a stale `healthy` claim.
```
