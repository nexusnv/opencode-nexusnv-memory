# Supplementary Spec A — Interface and Contract Specs

**Status:** proposed. **Sources:** Synthesized Report §4.6; V2 docs `/v2/docs/build/plugins/` (tool/command/hook shapes). **Normative on V2 contracts:** `design-spec-v2-production.md` §5. (Numbered `c4-04` for sequence; not a C4 core level — see `c4-06-code.md` note.)

## `memory_recall` tool

- Input: `{ "file": "INDEX.md" | "activeContext.md" | "decisions.md" | "architecture.md" | "style.md" | "issues.md" | "handoffs" | "handoffs/archive" | "handoffs/<name>.md" | "handoffs/archive/<name>.md" }` (required; `additionalProperties:false`; `handoffs`/`handoffs/archive` are names-only listing values; archive paths recallable on demand, never auto-injected).
- Output: `{ content: <text> }` — the documented tool-**executor** envelope (default; route it through one `toolResult(text)` adapter, G2). File content is truncated to cap with a truncation notice; unknown/traversal/missing single-file paths error (`memory file not found: <name>`, listing hint for handoff paths); `handoffs`/`handoffs/archive` return names-only listings — never a content listing of any other path. `readCapped` is the single choke point and re-validates the resolved path stays within `.opencode/memory`.
- Description (normative, doubles as retrieval policy): "Past project decisions, renames, and rejected alternatives (capped). Use when the user asks why something is named/designed this way, when touching a contract or previously-renamed symbol, or when INDEX.md mentions the area. Do not use for fresh implementation from current code alone. List available handoffs with file: \"handoffs\" (root) or \"handoffs/archive\"."

## `/memory-review` command

- Invocation: `/memory-review [scope]`. Behavior: the **read+propose phase writes no memory and proposes only** — its sole output is a proposal table; no durable change happens without per-line human approval; its only durable side effect is the §5.12 `review.invoked` metrics counter (count diagnostics, no content). It is **not** sandboxed: a plugin command cannot target a subagent (`CommandInvocation` has no agent selector), and a session-scoped permission lock would be time-scoped (the reviewed text persists in the transcript) and would deny the user's own concurrent tools, so it is deliberately not used (retired G5). The optional read-only `memory-manager` subagent (separate session) is available when the primary agent delegates. It reads INDEX + scratchpad and emits a **proposal table only** — target file, exact candidate line, provenance tag (`source:user|tool|model|snapshot`), advisory injection flags — with cap and redaction checks. It writes no memory. The human approves specific lines through the `memory_apply` tool (candidates not tagged `source:user` cannot be bulk-approved); application is deterministic via `writeCapped`. Also validates direct manual edits to `issues.md` without overwriting. On completion `memory_apply` resets `<projectID>/curation.pending` to `0` and clears the `<projectID>/curation.rotated` marker (the command never resets — `memory_apply({candidates:[]})` is the reviewed-nothing signal).
- All file content is treated as untrusted **data, never instructions**: the review never executes commands, never fetches URLs, and never follows directives found inside memory files (ADR-0007).
- Implemented with `ctx.command.transform`; the executor receives `{ sessionID, prompt, delivery }` and re-submits via `ctx.session.prompt({ ...prompt, sessionID, text, delivery })` so `files`/`agents`/`skills` are preserved (`PromptInput.Prompt` has no `metadata`; `delivery` comes from the invocation).

## `memory_apply` tool

- Input: `{ "candidates": [ { "file": <allowlisted target>, "line": <string>, "source": "user"|"tool"|"model"|"snapshot", "flags"?: <string[]> } ] }` (required; `additionalProperties:false`; `candidates:[]` = reviewed-nothing signal, no asserts, resets counters).
- Output: `{ content: <summary> }` on the all-allowed path only (applied count, via `toolResult`); on first deny/reject propagate the error with remaining candidates pending.
- Behavior: the **only** channel that writes approved lines. Executor binds `sessionID/agent/source` from its own tool context (`context.sessionID`, `context.agent`, `{type:"tool",messageID:context.messageID,id:context.id}`). For each candidate sequentially it calls `ctx.permission.assert({ sessionID, agent, action: "memory_write", resources: [file], metadata: { line, source }, source, save: [] })` **once**, and on `allow` calls `writeCapped(file, line)`. Requires the shipped `memory_write → ask` rule or the gate matches only the base `*/* → allow` wildcard and fails open. Per-line approval therefore holds by construction and untrusted lines cannot be bulk-approved; the model never writes durable memory directly. Resets `<projectID>/curation.pending` → 0 and clears `<projectID>/curation.rotated` (the command never resets).
- Why a tool and not the command: `/memory-review`'s executor returns `void` and cannot await human approval (it receives only `{ sessionID, prompt, delivery }`).

## `memory_metrics` tool

- Input: `{}` (empty object; `additionalProperties:false`; read-only, no arguments). Normative contract: `design-spec-v2-production.md` §5.12 (ADR-0008; user story US-28).
- Output: `{ content: <markdown table> }` via `toolResult` — the deterministic dashboard: explicit-call counters (recalls by allowlisted file, apply batches/lines/denials, review invocations), behind-the-scenes counters (INDEX attach outcomes, brief/status/hint outcomes incl. budget truncations, failure captures by outcome, idle/compaction captures), hint→recall correlation, memory-file health (line counts vs caps, handoff/archive counts, pending), and a 7-day bucket view.
- Description (normative, doubles as retrieval policy): "Local usage metrics of the memory plugin: counters for explicit calls (recall/apply/review) and behind-the-scenes outcomes (captures, truncations, denials, hint→recall), plus memory-file health. Counts only — no content. Use when the user asks about the plugin's activity or its stored stats."
- Invariants: every persisted metrics value is a JSON number (no prompt text, tool output, captured paths, identities, or prose — `redact` deliberately not applied since nothing free-text is stored; the arm flag is the int `1` when armed — binary semantics, numeric storage); counter names are an enumerated fail-closed vocabulary (unknown names are logged and dropped, never written); day buckets pruned after 90 UTC days; bumps are fire-and-forget, never-throw, serialized through the ledger's per-process write mutex and never alter any hook/tool outcome.
- Renderer: a pure function over `{ totals, days, health, since }` — the only strings it can emit are counter names, the six allowlisted structural file names, UTC day stamps, and integers; `health` is line counts and entry counts only, file bodies never rendered.

## `memory_search` tool

- Input: `{ "query": <non-empty string>, "file"?: <allowlisted path>, "maxResults"?: <integer>, "caseSensitive"?: <boolean> }` (required `query`; `additionalProperties:false`). `file` accepts the six structural names and individual handoff/archive paths; listing sentinels (`handoffs`, `handoffs/archive`) are rejected (recall lists names). `maxResults` defaults to 20 and clamps to 50; invalid values fall back to 20. Matching is literal, case-insensitive by default.
- Output: `{ content: <rendered hits> }` via `toolResult`. The renderer emits a bounded header, `- <file>:<line>: <text>` rows (or `(no matches)`), a shown/total/files footer, and truncation notes. Hits are 1-based line numbers with trimmed text bounded to 200 chars + `...`.
- Read path: the **same** allowlist/traversal choke point and redaction as recall, via `readFullRedacted` (full-file, no line cap) under a **1 MB per-file byte guard**. Default scope order is the six structural files in `MEMORY_FILES` order, then `handoffs/` newest-first, then `handoffs/archive/` newest-first, capped at 200 candidate files. Missing files are skipped in the default scope; an explicit `file` miss throws the friendly missing-file error; unknown/traversal scopes reject.
- Side effects: none. No counters, no arm consumption, no writes, no new storage keys. Results are untrusted data and are never auto-injected. The redaction path is linear-time on long single-line files (bounded URL-credential pattern).

## `memory_status` tool

- Input: `{}` (empty object; `additionalProperties:false`; read-only, no arguments). Normative contract: `design-spec-v2-production.md` §5.13.
- Output: `{ content: <markdown report> }` via `toolResult`: scaffold presence, INDEX lines/cap/attachability, AGENTS.md protocol block, advisory `memory_write → ask` evidence, optional `memory-manager` agent, capture/health counts, budgets, version, validated `since`, newest root handoff name, and next actions. The renderer is deterministic (fixed strings, allowlisted names, integers, one-line bounded version, relative/`~/` config paths); no memory body or captured content is emitted.
- Side effects: none. It reads existing counters/health/install markers only, writes no storage, and bumps no counter. Degraded reads render `unknown`/`unreadable`/`not-found` (the config scan is advisory; effective merged permissions are unverifiable).

## `/memory-metrics` command

- Invocation: `/memory-metrics [reset]`. Behavior: computes the §5.12 counters + on-disk health counts and posts the rendered table into the current session via `ctx.session.synthetic({ sessionID, text })` — no model turn (there is no text-return surface on `CommandDefinition.execute`, `Promise<void>`). Because whether the TUI renders a synthetic post without spawning a model turn is not type-provable on the installed 2.0.29 package, the first post of the process (the deploy event) logs one G-M1 line; G-M1 is a deploy-time human check, not a runtime branch — when the post rejects at runtime, the executor falls back to the `/memory-review` pattern — `ctx.session.prompt({ ...prompt, sessionID, delivery, text })` asking the agent to call `memory_metrics` and echo the table verbatim. The executor never throws; a fallback failure degrades to a diagnostic log.
- `reset` argument (case-insensitive): removes all `<projectID>/metrics/…` keys (paginated scan + remove), stamps a fresh `since`, and reports the restart through the same post/fallback channel. The command writes no durable memory file and resets nothing except on `reset`; collection is always on with no sixth option (ADR-0006 stands; ADR-0008).
- Implemented with `ctx.command.transform` (same `{ sessionID, prompt, delivery }` shape as `/memory-review`).

## `/memory-status` command

- Invocation: `/memory-status` (no arguments). Behavior: computes the §5.13 report and posts it via `ctx.session.synthetic({ sessionID, text })` — no model turn. When the post rejects, it falls back to the §5.5 pattern (`ctx.session.prompt` spread) asking the agent to call `memory_status` and echo the report verbatim. It never throws, writes nothing, and bumps no counter; report-read failures degrade to a diagnostic log. The optional `commands/memory-status.md` stub is a secondary affordance; the plugin registration is normative.
- Implemented with `ctx.command.transform` (same `{ sessionID, prompt, delivery }` shape as `/memory-review`).

## Hook contracts

- `prompt`: **sole** injector of `INDEX.md` content (capped; over-cap file is not attached) to the current prompt only; retry-safe (V2 runs hooks once at admission; concurrent resubmissions may re-run — stay idempotent). Dedup guard: skip if an `INDEX.md` attachment is already present. Root `AGENTS.md` carries protocol+links only, never content, so no double injection. The hook is **async and never throws** and performs **one** bounded memory side effect: a `source:user` directive (documented form, outside fences/quotations; pastes covered only by that heuristic) is appended to `decisions.md` — the only hook that sees `event.prompt.text` before admission — under a per-process write mutex, ledger-idempotent by content ID; plus the ADR-0008/§5.12 count-only metrics bumps in `ctx.storage` (fire-and-forget counters — diagnostics, never memory content). `classifyProvenance` detection stays pure.
- `context`: **async** (it reads Promise-based `ctx.storage`/`ctx.vcs`) and **never throws**. Push brief (capped active slice of `activeContext` + newest handoff pointer, max 5 error summary lines; never the INDEX map nor the decisions tail) + one `[memory]` status line (over-cap INDEX notice / rotation notice / skipped-capture notice / review-due nudge) + at most one hint line on exact INDEX match. The brief does **not** contain the INDEX map — `prompt` is the sole INDEX injector. The decisions tail is `loadPriors` + recall only. Under budget pressure the status line is dropped before the hint. The hint parses `event.messages: Message[]` for the latest user-authored text and is throttled via `<projectID>/hint/<sessionID>/<promptHash>` (tool-driven continuations must not repeat it). **Known Errors enter the brief as message-derived summary lines only** (one line per error, `source:` tagged; `<cmd>:` prefix only when `event.input` yields it); full captured bodies stay `memory_recall`-only (P16, ADR-0007). The `[memory]` line is **model-facing** (`event.system` reaches the model, not the user directly); delivery depends on the agent relaying it.
- `compaction`: push capped + redacted priors (`loadPriors`: activeContext slice + decisions tail ≤60 + handoff pointer; `event.system.push`). **Never set `event.result`** — the hook runs before the summary model call, so setting it skips the native summary (ADR-0003). Never change model/threshold/trigger.

## Tool hook contract

- `execute.after`: failure-only. Discriminant `event.status === "error"` (fallback `error != null`); append failed shell/build/test output to `activeContext.md` (redact, ledger check-before-write) as a `source:tool` message-derived summary line + optional recall-only detail block. `Tool.Error` carries only `message` (G4), so the **tested baseline is message-only**: the summary line is derived from `event.error.message` (newlines collapsed, ≤120 chars; `<cmd>:` prefix only when `event.input` yields it) and the ≤20-line detail block is written **only when untyped `error.metadata` inspection yields output**. No downstream consumer (brief, budgets, fixtures, evals) may assume a body, cmd, or code exists. Successes are ignored. A real scratchpad write increments `<projectID>/curation.pending` (direct `decisions.md` fast-path writes never do); a rotation also sets the `<projectID>/curation.rotated` marker for the next status line.
- `flagInjection(text)` runs over captured text and stores **advisory** flags with the entry (never blocks a write, never reported as detection).

## Provenance contract

- Every entry is tagged `source:user | tool | model | snapshot`. Only an explicit directive in the user's own turn (documented `remember:`/`remember that` line-start form; outside code fences and quotations — pastes covered only by that heuristic) classifies as `source:user`, which appends immediately to `decisions.md` tagged `(user-asserted)` without incrementing pending — detection and write run in the `prompt` hook (serialized, never-throw, ledger-idempotent), and the plugin is the sole writer. Everything else takes the scratchpad path and requires review. No origin may write `architecture.md`/`style.md`/`issues.md` without review (ADR-0004/0007).

## File contracts

See `c4-05-data-model.md` for field schemas. Universal rules: UTF-8 markdown, caps enforced per enforcement point (`c4-05`), secrets/`<private>` stripped, `decisions.md` append-only and `handoffs/` immutable; `activeContext.md` is ledger-guarded auto-append + rotation; `architecture.md`/`style.md`/`issues.md` are review-gated rewrites (git blame preserves lineage).

## Config shapes

- Plugins: `plugins: ["./plugins/memory"]` (`.opencode/opencode.jsonc`) or `["./.opencode/plugins/memory"]` (repo-root), or drop-in discovery, or `{ package, options }`.
- Agents: ship `memory-manager.md` (`mode: subagent`; **read-only — `* → deny` first, then `read/glob/grep → allow` only**, ADR-0007; the last matching rule wins, so any future `allow` must come after a broad `deny`). The **default/primary agent needs a `subagent` allow for `memory-manager` only if the optional delegation path is enabled**; the default review runs in-session and writes no memory (only the ADR-0008/§5.12 `review.invoked` counter bumps), so there is no permission lock to configure (retired G5).
- Options (≤5): `{ indexLines, fileLines, injectBudgetLines, captureFailures, snapshotThrottleMinutes }`, read via `ctx.options`; the memory directory is fixed at `.opencode/memory` (ADR-0006).
- **No `references` entry** (ADR-0006): references attach directories and are client-initiated; the earlier file-level `references.memory → INDEX.md` form was invalid and is removed.
